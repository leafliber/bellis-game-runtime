# G1 任务卡：只读感知

本卡保留原阶段的目标与出口。旧游戏的实机验证范围已[退役](../games/witch-trial.md)，当前验证任务见 [G2](G2.md)。

**目标**：维护者手动游玩时，主进程只读地看懂游戏。画面与游戏声音进入主进程，OCR、画面变化与签名、配音检测、剧情记录在《魔女审判》上给出正确结果；同一段录制在 M0 回放中得到同样的结果。全程不发任何输入。

**通用优先**（维护者 2026-11-01）：感知面向所有游戏，不针对《魔女审判》调参。模型与参数是插件的缺省，适配包只给 ROI 这类必须按游戏写的数据；配音检测只须在各种背景音下大致判出配音的忙闲、占用低，不求精准，使用方必须有不依赖它的兜底；每款游戏为只读感知须标定的项越少越好，标定了多少记入[通用度指标](../modules/offline-tools.md#离线回放基准)。

**平台**：同 [G0](G0.md)。模型推理在 CPU 上运行，GPU 按第一版的规则不测（[真机探针](spikes.md)）。

**必读**：模块文档[感知](../modules/perception.md)、[剧情记录与规划](../modules/narrative-planner.md)（剧情记录部分）、[游戏适配包](../modules/game-adapter.md)、[离线工具](../modules/offline-tools.md)（录制、标定、离线回放基准）、[实时核](../modules/realtime-core.md)的音频采集、[核协议](../modules/core-protocol.md)的帧环与音频环、[《魔女审判》适配](../games/witch-trial.md)；[技术基线](tech-baseline.md)中的 GR-04、GR-08、GR-10、GR-12、GR-14、GR-16、GR-27、GR-31；[合规](../compliance.md)的 C-1、C-4、C-5；[真机探针](spikes.md)中的 GS-04、GS-05、GS-06。

## 范围

做：适配包的声明格式与校验，合成游戏与《魔女审判》的适配包（必需部分、对白框的 ROI 与签名、语言核对）；音频环与 WASAPI 进程回环；`ocr@1`、`scene@1`（通用的变化与稳定检测、播片的识别、画面签名）、`voice-activity@1`、`narrative@1`（含播片段与播片的字幕）；模型制品的获取与核对；录制工具、样本格式与 M0 回放；只读运行的入口；GS-04、GS-05、GS-06。

不做：任何输入（真实输入后端、快路径的动作、逐步控制器）；VLM、planner 与任何模型外发（播片内容的理解由 G2 的 planner 以关键帧做）；画面状态服务与按通用画面类型的风险规则（G2，GR-32）；与 Bellis 的连接；提权时的计划任务启动；GPU 执行器；日文配置；选项、审判与坏结局的画面签名以及阅读节奏参数的标定（G2 的快路径用到时再做）；按《魔女审判》调配音检测与 OCR 的参数。

## 步骤

1. **适配包格式。** 按[格式](../modules/game-adapter.md#格式)：Pydantic 模型为 Schema 源，`tomllib` 读取，`uv run check` 校验 `games/*/` 下的每个适配包；`game-adapter@1` 把当前适配包交给其它插件。写合成游戏的适配包（ROI 取自它的渲染布局）与《魔女审判》适配包的骨架（窗口识别、语言、期望分辨率、合规声明、画面类型映射；ROI 与签名在第 9 步标定）。
2. **音频环与进程回环。** 按[帧环与音频环](../modules/core-protocol.md#帧环与音频环)加入音频环的布局与偏移表核对；实时核按[音频采集](../modules/realtime-core.md#音频采集)用 WASAPI 进程回环采集游戏进程（含子进程）的声音，PCM 带采集时刻写入音频环；主进程创建并读取；自动测试用假音频源。
3. **感知的取帧与 `scene@1`。** 插件取帧的接口，实时帧环与录制回放共用；通用的变化与稳定检测，含持续整屏动态的播片（维护者 2026-11-01：剧情中会穿插播片）；画面签名的判别（锚点模板、像素检查、OCR 固定文字），先在合成游戏上验证。
4. **`ocr@1`。** 按 [OCR](../modules/perception.md#ocr)：PP-OCRv5 经 ONNX Runtime，只识别 ROI，输出行文字、识别框、置信度、帧号与变换版本；模型制品按版本与摘要放进本地数据目录并核对；前后处理用现成封装还是自写随 GS-04 定；Windows 自带 OCR 作对照基线。
5. **`voice-activity@1`。** 按[配音检测](../modules/perception.md#配音检测)：从音频环读声音，通用的小型语音检测模型判断忙、闲或未知，带迟滞；参数是插件缺省，不按游戏调，GS-06 评测泛化与占用。
6. **`narrative@1`。** 按[剧情记录](../modules/narrative-planner.md#剧情记录)：一句的边界、修订号、完整度（部分、完整、缺口）、剧情范围、播片段与其中的字幕，存本机 SQLite；先在合成游戏上以真值核对。
7. **录制与 M0 回放。** 把帧、游戏声音与标注录到本地数据目录，留存上限按 C-4；样本格式写进[录制](../modules/offline-tools.md#录制)；M0 回放把录制喂给同一组插件，输出能与实时运行逐条比对。
8. **只读运行入口。** 按[只读运行](../modules/offline-tools.md#只读运行)：一条命令按适配包拉起实时核（帧环按期望分辨率定大小）、音频环与感知插件，实时显示画面状态、OCR、配音忙闲与剧情记录，可同时录制；不连 Bellis，不发输入。
9. **《魔女审判》标定与普查。** 按 C-5 在本机截图与录制上只标定只读感知必需的项：对白框的 ROI（对白文字、名字栏）、继续标记的签名，以及对白画面的签名（可行时；标不出就按[对白框](../modules/game-adapter.md#对白框)的通用缺省不写 `screen`）。语言核对的通用一层按文字系统自动进行，固定文字只在便宜时补一项。选项、审判与坏结局的画面形态、审判计时、坏结局与重来由 GS-05 普查并记录，它们的签名与阅读节奏留到 G2 的快路径需要时再标定。GS-05 的普查结论写回[《魔女审判》适配](../games/witch-trial.md)。锚点模板只存本地数据目录。
10. **探针与验收。** GS-04、GS-06 以合成样本为主测泛化与占用（多字体、多底色；多种背景音与增益），在录制上只做抽查与一致性核对；维护者手动游玩一段剧情（约 10–15 分钟，含对白、选项与审判），同时只读运行并录制，按出口逐项核对；结论改变设计时直接修改技术基线与相关文档。

## 出口

以下在 Windows 11 真机上实际运行通过，且 Linux 容器内的完整检查通过：

- 合成游戏与《魔女审判》的适配包都通过格式校验；语言核对在中文版的录制上通过，在合成的其它文字系统的样本上拒绝。
- 合成游戏在自动测试中经假采集源跑通 OCR、签名与剧情记录，结果与真值一致；它的播片被记成一个播片段，其中的字幕记成句子。
- 维护者手动游玩一段剧情时：剧情记录逐句正确，完整、部分与缺口的判定正确；遇到播片时记成播片段，对白画面与转场不误判为播片；对白画面被正确识别（或按通用缺省不靠签名也读对）；配音忙闲与对白的起止大致一致（[GS-06 的评测](../modules/perception.md#gs-06-的评测)里录制一项的口径），不要求逐句精准。
- 同一段录制在 M0 回放中得到同样的剧情记录；已标定的签名在录制上正确判别。
- GS-04、GS-06 在合成样本上的准确率、时延与占用按各自的口径实测记录，在录制上的抽查与一致性另记；GS-05 的结论写回文档；OCR 与语音检测模型的版本与许可写回 GR-10、GR-08。
- 《魔女审判》适配包里必需项之外为只读感知标定的条目数（ROI、签名、固定文字）记入报告，作为通用度指标的第一个数据点。
