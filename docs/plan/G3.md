# G3 任务卡：通用游戏桥与自主通关

**目标**：把 G2 的感知、规划与逐步控制接到 Bellis，形成产品自身的感知、选择、执行、核验与恢复闭环。在不直播的环境中以《魔法少女的魔女审判》从开局到游戏自身可核验的通关状态完成验证；操作员在场监督，游戏推进与选择由产品完成。人工试玩只用于标定、诊断与复核，不计为自主通关。

**通用优先**：连接、许可、目标、决策点、暂缓推进、失败记录与恢复只实现一次。游戏特有的画面映射、定位、签名和快路径留在适配包；Bellis 只接收摘要和事实，不复制 Runtime 的内部状态。保留关闭快路径的通用策略对照。

**前置**：Bellis P3 的契约经其仓库合入后才能更新锁定副本。真实游戏联调前须满足 [G2 出口](G2.md#出口)及[合规](../compliance.md)的适用条件；模型只使用已批准的账号、用途与型号。不直播的验收不授予公开推流或 M3 权限。

**必读**：[总体架构](../architecture.md)的权威与失效规则、[游戏桥](../modules/game-bridge.md)、[核协议](../modules/core-protocol.md)、[实时核](../modules/realtime-core.md)、[逐步控制](../modules/step-control.md)、[剧情记录与规划](../modules/narrative-planner.md)、[模型接入](../modules/models.md)、[游戏适配包](../modules/game-adapter.md)、[离线工具](../modules/offline-tools.md)、[技术基线](tech-baseline.md)的 GD-03、GR-05、GR-20、GR-28，以及 [Bellis P3](https://github.com/leafliber/bellis/blob/main/docs/plan/P3.md)与 [P-01–P-08](bellis-p3-proposals.md)。

## 步骤

1. **锁定与互通。** 按[契约](../modules/game-bridge.md#契约)锁定同一个已合入提交的 Schema、Pydantic 模型与夹具，纳入完整检查。实时核的 Rust 控制类型先尝试用 typify 从锁定 Schema 生成；不可行时按现有批准路线手写，并以 Schema 和夹具做双向核对。验证原始整数词法、范围、消息角色与方向、版本不兼容、未知字段以及两端单调时钟换算。
2. **双连接与许可源。** 主进程和实时核分别以语义、控制角色直连 Bellis 宿主，读取本次会话连接信息。沿用认证后的本机通道与已批准的输入权威；操作员独立运行和 Bellis 接入只能选一个许可源。主进程不能转发、延长或重新授予输入许可。连接断开、会话变化、许可失效与重启均按现有停止规则处理。
3. **语义桥插件。** 把授权目标交给 planner，把决定绑定到当前决策实例，并在新帧上重新定位核验。局面、候选、健康、前置条件、实际动作与失败记录按冻结契约上报；画面、OCR、模型候选均只作数据。未知执行结果停止推进并保留记录，不自动重发。先用合成游戏与假输入后端接真实的两端进程验证。
4. **节奏与可观测性。** 按 GR-20 从已观察事实产生看点标记，附配音忙闲；处理有到期时刻的 hold/release，本地上限兜底，计时选择保留优先级。语义链路传递 traceparent，记录首动作、选择、拒绝、许可释放与恢复的证据，避免把提议或请求当成已经执行。
5. **失败与恢复。** 验证坏结局、卡住、模型失败、旧回复、规划服务失效、人工接管、宿主退出与核重启。依赖恢复本身不放宽已锁存的停止状态；按现有操作员或 Bellis 授权目标恢复，保留尝试记录和未知结果隔离。选择的候选在余量线前更新，执行以当前实例与实际回执为准。
6. **真实游戏闭环。** 先在不直播的 M2 会话中完成对白、调查、选项及审判的完整段落，同时录制与记录轨迹，再持续覆盖通关所需的后续章节、场景和恢复。实测失败时修复对应通用模块或适配包并回归，不用人工代选补齐产品结果，也不通过游戏文件、内存或外部攻略推进。
7. **完整通关与复核。** 达到游戏自身可核验的通关状态后，核对从开局到结束的录制、决策与动作轨迹。中断和人工接管的片段明确标出；必要的恢复由产品在重新授权后完成。私有测试直播按 Bellis P3 的独立出口执行，不用非直播测试代替。

## 出口

- Windows 11 真机与本机 Linux 容器的完整检查通过；Bellis 对应变更的三平台 CI 通过。自动化与假后端结果不代替真机证据。
- 两端使用同一提交的契约，双角色认证、握手、时钟与消息验证正确；缺失前置条件或版本、适配包不符时不发输入。
- 急停、许可到期、接管、连接断开与进程退出后输入释放有真机测量及物理核验；不能把“发送抬起请求”记成“核验无残留”。
- 无计时选择、计时选择与余量线兜底都绑定正确实例；看点解说遵守频率上限与动作事实，暂缓推进到期恢复。
- 在不直播的受监督会话中，产品从开局自主完成全游戏通关所需的剧情、调查、选择、审判与必要恢复，有连续证据可复核。一段剧情只是中间里程碑。
- 快路径关闭的通用策略对照有结果，通关所需游戏差异位于适配包；通关证据、录制、游戏派生数据与真实配置只保存在本地，不入库。
- 未运行或不能核验的项目写 PENDING；结论改变设计时直接更新规范正文与技术基线。
