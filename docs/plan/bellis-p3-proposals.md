# Bellis P3 契约提案

Game Runtime 需要 Bellis 配合的改动，在 Bellis 游戏桥契约冻结（P3 开工前）时提出。契约以 Bellis `packages/protocol` 为源（GD-03），下列条目须在 Bellis 仓库审核并合入后，本仓库才更新锁定的生成物。

本文件只写要 Bellis 改什么、为什么；Game Runtime 侧的行为写在“本仓库”一栏所指的文档。命名沿用 [Bellis 游戏桥](https://github.com/leafliber/bellis/blob/main/docs/modules/game-bridge.md)的约定：命令用 `对象.动作`，事件用 `对象.过去式`。字段名是建议，以 Bellis 冻结的为准。

## 契约提案

| P-01 | 实时核的控制连接 | 接受实时核以角色 `game-runtime.core` 直连宿主，这条连接只承载 `lease.renew`、`input.stop`、`input.released` 与实时核健康，其它消息一律拒绝；令牌与到期时间直接给实时核；主进程以 `game-runtime.main` 走语义连接；控制连接不在时，游戏桥插件不申请也不续约 `game.input` | GR-05，[连接](../modules/game-bridge.md#连接) | 游戏桥、安全核 |

### P-09 未决状态与结案

方向已批准，源契约冻结与双端验收为 PENDING。

1. 协商后的语义健康须区分普通卡住与物理未决，报告被控对象的未决尝试、原会话与动作关联，并将该对象报告为未就绪。Bellis 在发可执行目标或申请输入许可前回读并持久记录隔离。空读数、新目标及重连不能清除已记录的隔离。
2. 结案经操作员入口与安全核执行闸门批准，由 Bellis 与 `game-runtime.main` 的认证语义连接传递。结案关联同一对象与原尝试，区分确认执行、确认未执行及人工完成核对但无法确定历史执行结果。Runtime 持久记录后确认，相同重送幂等，冲突或不匹配拒绝。应答丢失可重送取回原结案。Runtime 侧的状态与放行顺序见[动作尝试与未决结案](../modules/game-bridge.md#动作尝试与未决结案)。
3. 结案与任务能力仅在兼容的语义连接协商后启用。回读失败保持隔离。新增字段、请求与应答结构、版本及迁移以 Bellis `packages/protocol` 冻结的源契约为准。

### P-10 授权任务身份

方向已批准，源契约冻结与双端验收为 PENDING。

1. 握手须核对来自可信配置的固定被控对象标识，并关联跨进程的任务和未决账目。配置冲突、多目标歧义或无法关联原账目时拒绝执行。
2. Bellis 持久登记操作员获准开启的任务，向 Runtime 提交任务标识、根目标、单调时钟截止及可选的确定性整体完成条件。相同任务与参数重送按原结果处理，冲突拒绝。开启任务建立授权范围，具体执行仍经过目标与输入许可流程。
3. Bellis 从当前任务的可信绑定注入任务身份。Director 只能在该任务内提议目标和恢复。暂停、投票及 P-04 恢复使用同一任务，保持根目标和终局条件。语义健康提供任务回读，开任务或重连后先确认回读与 Bellis 原绑定相符且 P-09 允许，再申请可执行目标或新输入许可。终止的任务不能续用。Runtime 账目与开启顺序见[授权任务](../modules/game-bridge.md#授权任务)。
4. 任务消息及字段、根条件编码、版本及迁移以 Bellis `packages/protocol` 冻结的源契约为准。

## Bellis 侧的其他遗留

这些不是契约改动，但同样须在 Bellis 侧处理：

- **R-17 的 GLM 接入点**：决策模型会收到游戏内容，须在 T1 前核对经 Agent Plan `/api/plan/v3` 调用的 GLM 是否走已启用安全沙箱的接入点，否则换模型（[合规 C-2](../compliance.md#c-2-的依据与条件)）。
