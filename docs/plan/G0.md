# G0 任务卡：工程骨架与实时核闭环

**目标**：证明两进程的骨架成立。主进程与实时核按规则启动、认证、心跳与停止；实时核把游戏窗口的帧写进帧环，主进程能读到；动作块经假输入后端执行，[失效与释放](../architecture.md#失效与释放)中的每种情形都按规则停止输入并释放。

**平台**：采集、命名管道与跨完整性级别的验证在 Windows 11 x64 真机上验收；完整检查在 Windows 真机与本机 Docker 的 Linux 容器上运行并必须通过，不用托管 CI，macOS 不验证（GR-29）；Windows 专有部分放在接口后面并提供假实现（见[总体架构](../architecture.md#平台)）。

**必读**：[总体架构](../architecture.md)；模块文档[实时核](../modules/realtime-core.md)、[核协议与本机通道](../modules/core-protocol.md)、[主进程插件内核](../modules/plugin-kernel.md)；[技术基线](tech-baseline.md)中的 GD-01–GD-05、GR-01–GR-03、GR-07、GR-28–GR-30；[真机探针](spikes.md)中的 GS-01、GS-03；Bellis 的[本机通道认证 R-05](https://github.com/leafliber/bellis/blob/main/docs/plan/tech-baseline.md) 与[插件内核](https://github.com/leafliber/bellis/blob/main/docs/modules/plugin-kernel.md)。

## 范围

做：仓库骨架与统一检查（含 Linux 容器）；核协议的生成管线；本机通道；主进程插件内核的最小实现；实时核作为非提权子进程的启动与停止；帧环与 WGC 采集；合成游戏夹具的状态机、渲染与窗口外壳；动作块、控制产出者心跳与假输入后端；GS-01、GS-03 两项探针。

不做：真实输入（SendInput、钩子、持键账目的真实释放）、音频、OCR、VLM、剧情理解、任何适配包（含合成游戏的，G1 以声明格式给出）、与 Bellis 的任何连接、提权时的计划任务启动（只做 GS-03 探针）。这些从 G1 起按[路线图](roadmap.md)的阶段实现。

## 步骤

1. **工程骨架。** 按[仓库与目录](../architecture.md#仓库与目录)建立 `core/`、`runtime/`、`protocol/`；Python 工程（Python 3.12，uv，锁文件入库，ruff、pyright、pytest）与 Rust 工作区（`rust-toolchain.toml` 锁定 stable 版本并写回 GR-01；cargo fmt、clippy、test；`windows` crate）；统一检查入口 `uv run check` 与在 Linux 容器里跑同一检查的 `uv run check --linux`；在 AGENTS.md 补全常用命令。
2. **核协议生成管线。** 按[核协议](../modules/core-protocol.md#核协议)建立 Rust 类型 → JSON Schema → Pydantic 的生成与过期检查，验证两个生成器对内部标签联合类型的配合；按[帧环与音频环](../modules/core-protocol.md#帧环与音频环)导出并核对帧环头部的偏移表。
3. **本机通道。** 按[本机通道](../modules/core-protocol.md#本机通道)实现 Python 服务端与客户端、Rust 客户端，含已知答案测试与 Python–Rust 互通测试；Windows 真机实际跑命名管道，Linux 容器跑 UDS。
4. **主进程插件内核（最小）。** 按[主进程插件内核](../modules/plugin-kernel.md)只做 G0 用到的部分：清单与配置校验、服务目录与 WAITING 原因、生命周期与有限次退避重试、可撤销注册、profile、控制产出者的 QUIESCING。
5. **实时核的启动与生命线。** 按[启动与生命线](../modules/realtime-core.md#启动与生命线)实现非提权子进程的启动、R-06 停止顺序与 Job Object、核连接上的控制产出者心跳、断开即释放后退出、重启先释放。
6. **合成游戏夹具。** 按[合成游戏](../modules/offline-tools.md#合成游戏)实现状态机、Pillow 渲染与 tkinter 窗口外壳：对话逐字显示、选项、计时选择、菜单、商店、弹窗与坏结局；状态机接受假输入后端回送的动作。
7. **帧环与采集。** 主进程创建帧环，实时核按[画面采集](../modules/realtime-core.md#画面采集)写入；假采集源从合成游戏的渲染缓冲取帧供自动测试使用。窗口识别规则先以配置给出，游戏适配包在 G1 接入。
8. **动作块与假输入后端。** 主进程按[动作块](../modules/core-protocol.md#动作块)提交；实时核只在[权威规则](../architecture.md#权威)的三个条件同时成立时把动作交给假输入后端，否则不发并释放；假输入后端把动作回送合成游戏的状态机，点击是否命中可证。G0 的许可来自测试用的本地许可源，只给假后端用。
9. **探针。** 在真机上运行 GS-01 与 GS-03，结果写入不入库的报告；结论改变设计时直接修改技术基线与相关文档。

## 出口

以下在 Windows 11 真机上实际运行通过，且 Linux 容器内的完整检查通过：

**骨架与协议**
- `uv run check` 在 Windows 真机与 Linux 容器内通过；生成物过期、帧环偏移表不一致时检查失败。
- 本机通道：未认证即拒绝，篡改、重放、超长帧与超时都被拒绝；Python 与 Rust 互通。

**进程与失效**
- 主进程停止时实时核按 R-06 的顺序退出，不残留孙进程。
- 假后端上验证[失效与释放](../architecture.md#失效与释放)：主进程崩溃或卡死、采集冻结、许可过期、旧代次的动作块、更换控制产出者，各自都停止输入并释放全部持续状态；实时核崩溃重启后先释放再接受动作。

**采集**
- 合成游戏：真机上其窗口经 WGC 进入帧环；自动测试中帧经假采集源进入帧环，假输入后端的点击回到状态机并改变画面。
- 《魔女审判》窗口在窗口化与无边框模式下持续进入帧环，遮挡、移动、最小化时帧与坐标变换正确（DPI 缩放不测，见 GS-01）；帧龄、丢帧与黄色边框的结论按 GS-01 实测记录。
- GS-03 有结果，结论已写回 GR-06 与 GD-02 的相关文档（或确认不需要改）。

假后端上测得的时序不代表真实输入的表现，真实输入在 G2 实测。
