# 《魔法少女的魔女审判》适配

首个里程碑的游戏（Bellis D-06）。本文只写这款游戏特有的适配；通用机制见各模块文档，合规约束见[合规](../compliance.md#魔法少女的魔女审判)。适配包在 `games/witch-trial/`，见下文的[适配包](#适配包)。

## 版本与语言

（GR-16）简体中文版，整局固定不换。

- 2026-10-28 读取 Steam 商店页：目前只有简体中文（界面与字幕）与日文（界面、全程配音与字幕），配音只有日文。
- 适配包写明语言 `zh-Hans`；锚点模板与各 ROI 按中文版标定。语言核对的通用一层按汉字比例，简体与繁体的区分靠可选的固定文字（[语言核对](../modules/game-adapter.md#语言核对)）。GS-04 的真实样本取自中文版的录制，暂不准备日文配置。
- 启动时的语言核对按[游戏适配包](../modules/game-adapter.md#内容)的必需项执行；不支持中途换语言。
- 依赖原文文字游戏而译文没有处理好的推理，按[坏结局与重来](../modules/narrative-planner.md#坏结局与重来)或由操作员接管处理，不为此改用日文版。

## 运行要求

- 窗口化或无边框全屏；不需要提权（[界面与流程](#界面与流程)）；失焦时的行为待普查。
- 只有逐步模式，模式仲裁始终选逐步控制器。
- 画面类型到[通用分类](../modules/perception.md#画面状态)的映射：对白为对话，选项为选择，审判为计时选择，另有设置、存读档与坏结局；没有商店、地图与背包（GS-05 核对）。

## 界面与流程

GS-05 的普查结论。2026-11-01 在中文版第一章开头约 13 分钟的录制上得出（窗口化 2560×1440，游戏设置未改；编码助手按 C-5 代为操作，只用鼠标）：

| 项 | 结论 |
| --- | --- |
| 对白 | 文字直接叠在场景上，没有不透明的对白框，至多三行，左缘约在客户区宽度的 22%。有名字时左上是菱形底的名字栏，首字放大并着色；未知的角色显示为“？？？”；旁白没有名字栏；心里话加括号。典狱长借屏幕说话时文字下多一条半透明的暗带 |
| 继续标记 | 右下角的菱形图标：开始逐字显示即消失，显示完后约 0.2 秒内淡入，之后以约 2.3 秒为周期明暗闪烁，最暗时约 0.3 秒看不出。自动模式下不显示 |
| 逐字显示 | 缺省文字速度下约每秒 25–35 字，两行的一句约 0.8–1.2 秒显示完；左键点击推进 |
| 自动模式 | 左下角的 Auto 开关。没有配音的旁白每句约停 1.5–3 秒，有配音的随配音长短，长的十几秒；打开系统菜单时自动关闭 |
| 系统菜单 | 右上角的齿轮，鼠标悬停时放大。打开后是手机样式的面板：保存、读取、历史记录、选项设置、返回标题画面，右上角是关闭。序章开头的牢房里点齿轮没有反应，到会客厅才打开。面板上的按钮只随悬停高亮、点不进去，关闭按钮也是（computer use 的点击，原因未查明，GS-02 用实时核的 SendInput 复核）；点面板外即关闭面板，同时推进一句 |
| 读取画面 | 换场景时全黑，右下角一个转圈的图标，约 1–2 秒 |
| 过场 | 竖条擦除、淡入淡出 |
| 提权 | 不需要：非提权的实时核采到了画面与声音，非提权进程的点击游戏能收到（UIPI 会挡住对提权窗口的输入） |
| 购买入口 | 系统菜单里没有商店或购买；标题画面未查 |

还没普查到的：选项、审判（计时的时长与超时的结果）、坏结局与重来、存读档与设置画面的内容、历史记录、标题画面、失焦时的行为；剧情中穿插的播片（多长、有没有字幕与字幕的位置、点击会不会跳过、放完要不要点击、自动模式下怎样）。

## 快路径

以下快路径是本游戏的必需项：对白推进与计时审判按[控制的组织](../architecture.md#控制的组织)中有时限的画面与高频动作须有快路径的规则；选项与失败与重来是本游戏的决定，让决策点与坏结局的识别不依赖模型（GR-15）。

| 快路径 | 内容 |
| --- | --- |
| 对白推进 | 名字栏与对白框的 OCR；文字完整、配音为闲且已过最短阅读时间后推进（[配音检测](../modules/perception.md#配音检测)） |
| 选项 | 识别选择画面，生成决策点 |
| 计时审判 | 识别审判发言与剩余时间；发言出现即增量计算候选，到余量线执行排第一的候选 |
| 失败与重来 | 以画面签名识别坏结局或游戏结束画面 |

这些快路径手写；[经验快路径](../modules/game-adapter.md#经验快路径)的记录可以先开启。

审判中点选发言里的某个词按[决策点](../modules/step-control.md#决策点)中字符级定位的规则处理，可行性由 GS-04、GS-05 实测。计时的时长与超时结果由 GS-05 普查。

## 动作白名单与风险

- 不允许长按。
- 快进、自动模式、回想与存读档不进动作白名单。
- 预计为买断制、无内购（GS-05 核对）；存读档与设置画面只允许返回。
- 系统菜单的面板上点面板外会关闭面板并推进一句（[界面与流程](#界面与流程)）：关菜单只用面板的关闭按钮，它点不进时交给操作员，不靠点面板外关闭。
- 坏结局画面上游戏自带的重来入口，只在画面类型为坏结局时加入白名单。游戏没有重来入口、只能回标题读档时，同样按状态加一条受限的“读最近的自动存档”流程，形式由 GS-05 普查后定。
- 不在决策点前主动存档；跨场直播的存档靠游戏的自动存档，或由操作员在下播时处理。

## 适配包

`games/witch-trial/` 写了必需部分（[格式](../modules/game-adapter.md#格式)）与只读感知要用的对白框：

| 项 | 内容 |
| --- | --- |
| 窗口识别 | 进程 `manosaba.exe`，窗口类 `UnityWndClass`，标题 `manosaba` |
| 期望分辨率 | 2560×1440 |
| 合规声明 | 按[合规](../compliance.md#魔法少女的魔女审判)：文本只取自屏幕，不用于训练，不记录真人示范；录制留存上限 50 GB（C-4）；允许的模型只有接入点 `glm-5-3-flash-260828`，各用途的型号经 GS-07 对照后再加 |
| 白名单 | 只有左键点击，落点为整个客户区；不允许滚动与键盘。可用的按键、要设为静态禁区的界面按钮由 GS-05 普查后再加；按住时长 0.05 秒、每秒至多 2 个动作为暂定值 |
| 画面 | 对白、选项、审判、设置、存读档与坏结局六个画面，映射按[运行要求](#运行要求) |
| 风险 | 暂为空，随 GS-05 补充 |
| 对白框 | 名字栏 `speaker`、对白文字 `dialogue` 与继续标记的签名 `dialogue-continue`（[对白框](../modules/game-adapter.md#对白框)），不写 `screen`，按通用缺省在每个不是过场的帧上读。ROI 取自录制上以 OCR 量出的全部识别框：对白文字的各行落在 x 561–1937、y 1161–1368，名字落在 x 388–936、y 930–1137，ROI 各留了余量；对白文字的 ROI 右边止于继续标记之前，否则标记会被读成“回” |
| 对白画面 | 签名 `dialogue` 不标：唯一稳定的界面元素是右上角的齿轮，鼠标悬停时它会放大，模板就认不出，录制中这样持续了几分钟；底边的花纹是半透明的线条，在亮的场景上反差倒过来，也认不出。不写 `screen` 的代价是别的画面落在对白文字 ROI 里的字也会被记成句子，G2 有了选项与审判的签名后再看要不要补 |
| 继续标记 | 签名 `dialogue-continue` 两个锚点：先看继续标记（`min_score` 0.6），再看底边中段的黑色荆棘（0.8）以认出游戏界面。在录制的 4880 帧上：逐字显示中的帧得分都不超过 0.44；标记亮着的帧都在 0.85 以上，半亮的大多在 0.68 以上；荆棘除了全黑的读取画面都是 1.0。模板从录制裁出，只在本地数据目录里 |
| 尚未标定 | 选项与审判发言区的 ROI，对白、选项、审判与坏结局的签名；固定文字与阅读节奏不是标定项，用通用缺省（通用优先，2026-11-01）。G2 的快路径需要时在本机截图与录制上按 C-5 标定 |
