# 逐步控制

逐步模式下唯一的控制产出者：逐步控制器每步在快路径与通用视觉智能体之间选择，定位目标、核对风险、交实时核执行、再核验效果（GD-04、GR-13）。这里还写动作风险的执行与模式仲裁。属于主进程关键平面，提供 `policy@1`（[策略后端契约](#策略后端契约)）。G2 实现；技能库在原神阶段。

## 职责

- 在画面稳定或通过 GR-38 动态准入时决定下一步动作。
- 把模型给出的目标定位到可核验的界面元素上。
- 按风险等级拒绝或改走决策点。
- 识别选择画面并生成决策点，执行 Bellis 的选择。
- 执行后核验预期效果。
- 决定当前由哪个后端担任控制产出者。

## 不负责

- **业务选择。** 选项、出示证据、指认人物一律经决策点交给 Bellis（Bellis D-07）。
- **规划目标。** 当前目标来自 [planner](narrative-planner.md#规划)。
- **最终把关。** 白名单、静态禁区与释放由[实时核](realtime-core.md#输入代理)执行。

## 每一步

1. 取新帧，经 `scene@1` 确认画面稳定，或按[动态准入](#动态画面的定位与准入)核对交互。过场和播片中停止动作，连续播片超过 `cutscene_timeout`（缺省 10 分钟）计入卡住。签名确认的计时选择可在倒计时局部变化时重新定位选项和执行已确认的决定。
2. 有快路径签名命中，由快路径决定动作；否则交给通用视觉智能体。
3. 定位目标、核对风险，输出一个统一动作空间中的动作交实时核执行。
4. 再取新帧，核验预期效果；通过的动作按[经验快路径](game-adapter.md#经验快路径)记录。

快路径的坐标取自当前帧的 OCR 识别框。动作之间的最短间隔按[适配包与通用缺省](game-adapter.md#阅读节奏)取值，同时遵守动作白名单的频率上限。

主进程用 `step_control.supervise` 组装操作员连接、实时核、感知插件和控制产出者。操作员控制台直接向实时核授予测试许可。缺少有效许可、已变画面的识别结果、无帧和陈旧帧均使控制器等待或拒绝。启动和转场后在已声明固定文字的画面执行语言核对，不符时停止控制。

一次提交只包含一个即刻动作。接受动作块后按动作身份等待回执。在输入后端执行时刻之后采集的新帧上核验效果，稳定路径用新稳定帧，动态路径见[效果核验](#动态画面的定位与准入)。实时核在提交与执行时分别检查期限与授权。

## 画面类型

画面类型只从[画面状态](perception.md#画面状态)读取，带来源与置信度（GR-32）。观察只能收紧限制，不能放宽：[动作风险](#动作风险)的第一道防线以签名为准；[按坐标执行](#定位与吸附)与[模式仲裁](#模式仲裁)以签名判出的类型为准，没有签名时才用观察，观察为危险或未知时不按坐标执行、不切换。

## 对白推进

已识别的对话画面有适用的对白框时，逐步控制器等待 `narrative@1` 处理该帧并确认当前句完整。按同一修订的完整帧采集时刻计最短阅读时间。此前剧情范围里读过的完整句用重读参数。配音按[配音检测](perception.md#配音检测)和[阅读节奏](game-adapter.md#阅读节奏)处理。缺剧情记录时继续等待，缺配音服务时按配音未知处理。

启用 `fast_paths` 时，签名确认的对白画面可按[对白框的 `advance` 声明](game-adapter.md#对白框)生成一步推进。等待阅读或配音期间保持等待。关闭开关或当前目标需要智能体判断完成时，达到相同阅读条件后交给通用视觉策略。无论从哪个后端得到提议，提交前按当前完整句、当前帧的 OCR 和最新配音状态再次核对，然后经过动作风险和实时核授权。

快路径用对白记录拼装同帧观察，点击当前文字的唯一识别框，以点击行在新稳定帧上消失核验效果。提交被拒或有明确未执行回执后，可从新帧重新提议。已执行且在同一帧段核验为无效果时，按[推进类重发规则](#动作分类与重发)重新定位并至多重发一次。物理结果未知时按[未决结案](game-bridge.md#动作尝试与未决结案)处理。

## 通用视觉智能体

**输入**：当前帧（受[合规 C-2](../compliance.md#合规确认) 的允许清单约束）、当前目标及其完成条件、最近几步的动作与结果、动作白名单说明。模型按[模型接入](models.md#按用途配置)的“智能体”用途调用。

**输出**（GR-19、GR-23）：

- **观察**：一句有长度上限的短描述，含画面类型、可交互的东西、与上一步相比的变化。
- **至多 3 步动作**（可配置），每步附目标描述与预期效果（画面有无变化、某段文字出现或消失、某个签名命中、画面类型变化）。业务选择只能输出“开决策点”。

**观察的来源与去向**（GR-19）：

- 不单独调用 VLM 描述画面。快路径画面的描述由快路径的结构化结果拼成（对白的名字与当前这一句、选项文字与编号、审判第几句发言与剩余秒数），不调用模型。
- 同一观察范围内沿用已接受的观察。过场后重新观察。动态路径的局部感知证据独立于模型观察发布。
- 观察用作局面摘要中的画面描述，并以“画面观察”写入[剧情记录](narrative-planner.md#剧情记录)。观察是不可信数据，存储与剧情记录相同。
- 不为与 OCR 交叉核对单独调用 VLM：OCR 置信度低的行在剧情记录中标出，由 planner 结合上下文判断。

### 通用自动闭环

（GR-38）planner 拆分授权任务，策略后端按需提议。逐步控制器从 `PlannerPort.current()` 读取当前子目标，在两次策略调用间用[快速本地感知](perception.md#动态界面证据)跟踪控件和核对风险，从新帧定位后提交一次输入，再核验效果与完成条件。观察、动作提议和预期效果都是数据。动态准入、新帧完成和[双端任务与结案](game-bridge.md#授权任务与动作尝试)的交付状态为 PENDING。

**交互实例。** 发出策略请求时绑定原 `SceneUpdate` 的帧号、采集时刻、变换版本、`observation_scope`、会话、控制产出者代次、目标代次及截止。由画面入口、布局锚点和控件组建立交互实例。跟踪证据只在该轮提议的采集序列内使用。目标在策略返回后才确定时，须从原帧起逐帧核对它一直属于同一交互实例，才可在新帧定位。换场、遮挡、目标消失、重名歧义、无法解释的布局变化、帧源中断及权限换代使实例失效。相同文字或图像重现时重新观察。`SceneService.observe` 和 `with_ocr` 仍以原帧发布观察及 OCR。

| 状态 | 后续处理 |
| --- | --- |
| 观察或等待策略 | 同一时刻至多有一个在途策略请求。失效时合并帧更新，从最新有效观察重提议，累计[任务预算](game-bridge.md#授权任务与动作尝试)。 |
| 新帧定位 | 目标、局面、风险或授权改变即丢弃提议。从新画面核验后再规划，或使用已声明、获准的安全返回入口。 |
| 等待执行与效果 | 使用[原动作尝试](game-bridge.md#动作尝试与未决结案)的回执和期限核验。确证未执行时从新观察重新提议。普通无效果依[重发规则](#动作分类与重发)处理。未决期间只读观察。 |

| 交互 | 自动处理 |
| --- | --- |
| 普通推进、导航与菜单 | 验证当前控件组与目标后定位。设置、商店等受限界面只走安全返回。对白适用完整句、配音与节奏门禁。 |
| 调查 | 打开已核对的普通调查入口，核验详情、目标状态或新证据。不可逆的提交或指认经决策点。 |
| 离散选择 | 从当前画面构建唯一选项和实例，经[决策点](#决策点)处理自选、投票和恢复。 |
| 计时选择 | 保留签名、计时 ROI、余量线及当前决定的[决策点规则](#决策点)。 |
| 失败恢复 | 当前授权内优先重观察、重规划及已核验的安全返回。坏结局按[重来入口](#重来入口)恢复。 |

#### 子目标与终局

控制器在全帧稳定门前为可动态核验的 `Goal.completion` 取连续新帧证据。会话、语言、播片、决策等待和期限检查继续生效。签名与画面类型逐帧核对。文字条件使用 `_matches` 中的只读谓词和 `verify_ocr` 校验的同帧结果，持续核对证据 ROI 可见、条件成立。末帧裁片相同时可复验原 OCR 读数，裁片变化时重读。文字消失还须核对同一区域仍可见且读数有效。

最后一次异步取证后复核末帧、任务与目标代次、权限和截止。当前目标仍获授权且没有在途或未决尝试，才经 `_complete_goal` 标记 `SessionProgress.goal_done`，向 `PlannerPort.on_goal` 发当前代次的 `GoalEvent(kind='completed')`。子目标和整体条件的绑定及状态推进见[规划](narrative-planner.md#规划)。`GoalJudgment` 依[多步执行](#多步执行)保留原观察门禁。

#### 动态画面的定位与准入

同一控制器处理无对白的菜单、调查、导航和选择。最小适配遵循 GD-04，快路径、签名及整组选项 ROI 按需补强证据，计时执行依[决策点](#决策点)核对。控件组和目标从当前画面取得，无需逐游戏背景掩码或逐按钮标定。

1. **关联轨迹。** 相邻已判帧先按控件组、相对锚点、角色和几何连续性筛匹配，再核对框重合、归一化 OCR 文本或原图裁片的视觉特征。仅接受分数达门槛、与次优有足够差距且短时连续的唯一关联。布局移动时可按组内坐标找回目标。目标离开视野、归属变化、状态不明或出现歧义时终止轨迹。
2. **末帧定位。** 控件身份、组连续性、可见性和模态检查各自达到审核门槛时，控制器从最近一张已完成取证且仍新鲜的帧上计算可见落点。提交前遇未判别的变化，用[动态界面证据](perception.md#动态界面证据)复查命中区、遮挡与风险。无法按时排除疑点即丢弃提议。在途提议继承已识别的限制。全帧可为 `CHANGING`，但目标和相关区域须保持同一交互和可用状态。
3. **提交。** 最后一次异步定位后重新核对帧龄、窗口、变换、交互实例、授权、暂缓和剩余时间。用核验帧作 `base_frame`，经 `ControlGrant.submit` 和实时核许可执行。动作有效期缺省 250 ms，同时受命令、任务与决策的更早绝对截止约束。刷新和排队不续期。
4. **效果。** 执行回执后的新帧须能证实原尝试的签名、类型、文字或可区分的控件状态变化，例如详情面板确实出现。提交前的状态用于区分新效果。单纯背景变化、光标移动和识别抖动不足以核验。证据不足时走[未决处理](game-bridge.md#动作尝试与未决结案)。

**未知画面。** 无签名时保留 `UNKNOWN` 限制。只接纳唯一吸附且结果可核验的低风险导航，包括打开或切换可辨认的只读信息页签，经明确返回控件回到可核对的上级页面。执行代码核对共享导航动作表、控件角色和层次、可见文字或已批准的通用图标、全窗风险及预期效果。模型给的动作类别和裸坐标均不能作为放行依据。发现成组互斥选项或不可逆操作时拦截普通输入，证据足以绑定选项实例时开决策点。执行须通过既有非未知画面、选项与 Bellis 授权门禁。禁用操作直接拒绝，缺少风险、倒计时或目标准确定位证据时观察并重规划，耗尽预算则报卡住。

[动作风险](#动作风险)的硬条件独立于感知置信度。已识别的转场、危险、歧义和失权使普通输入失效。仅在 [GS-09](../plan/spikes.md#gs-09-的评估) 审核的感知范围内启用动态准入。覆盖不足时可从新观察按既有全帧门禁核对。纯图标和模态检测的交付状态见[界面元素检测](perception.md#界面元素检测)。采样外状态、画面不可见的效果和连续实时控制超出本路径，连续控制见 [GS-08](../plan/spikes.md#真机探针)。

#### 闭环验收

1. 同一个控制器以同一套参数跑至少两种无对白文字布局，例如有非线性动效的纵排菜单与多处闪烁的顶部工具条。关闭快路径，不使用逐游戏掩码。在全帧持续 `CHANGING` 且原 scope 已失效时完成文字导航或调查。各自注入目标内外的小无字模态、半透明遮挡、危险词、禁用态、同图切回、重名、断帧和迟到提议。小范围原图变化须触发复查，已知风险或冲突须阻断提交。覆盖图标目标、未知画面的限定导航与决策等待，以及计时选择和失败恢复。对照严格原 scope、全帧稳定及全像素复验，固定滚动仅用于严格对照。
2. 使用真实 planner 与逐步控制器，回放签名子目标与操作员授权的整体文字终局。从取证到核验完成全帧持续 `CHANGING`，起帧与末帧 scope 不同。核对两次 `GoalEvent(kind='completed')` 分属当前子目标和整体代次，最终读出 `Status.COMPLETE`。标题、坏结局、无有效文字读数和过期判断不能发完成事件。
3. 用假显示、真实 Rust 核与假输入检验动作基帧、变换、期限、回执和效果。分别在请求已写出尚未收到回执、收到回执尚未证实效果、效果已转未决时换目标或暂停，确认旧尝试独立核验，最多提交一个输入。覆盖提交前后、回执后及结案应答前崩溃。用 P-04 换目标、投票、暂停与重连分别耗尽同一任务各项预算。重送开任务请求保持预算，只有经授权的新任务且旧尝试与输入释放都结清后才开新账。授权、禁区、截止及决策归属的硬门禁负例须无违规提交。
4. 先用已有 OCR 和 OpenCV 验证可读目标、连续性及失效流程。覆盖不足的感知能力保留为 unsupported。检测器、指标及真实画面盲测按 [GS-09](../plan/spikes.md#gs-09-的评估) 执行。真实自主输入须通过[语义契约与账目的双端验收](game-bridge.md#授权任务与动作尝试)及各游戏合规验收。

## 多步执行

（GR-23、GR-38）逐步控制器每步用 `scene@1` 与 OCR 核对预期效果。稳定路径按新稳定帧核验。动态路径每轮只提交一步，核验执行后新帧的明确效果。旧观察只归原 scope。原 scope 已变化时，本轮首步仍可用连续交互证据通过[动态准入](#动态画面的定位与准入)在新帧定位。执行后若原 scope 已失效，丢弃该范围内的余下步骤，从核验效果后的新观察重新提议。

- 通过：在当前帧上按 OCR 文字或界面元素重新定位下一步的目标再执行，不复用旧坐标。
- 未通过，或下一步的目标只能由 VLM 给坐标：停在这一步，以新帧再调用智能体。
- 每一步照常核对[动作风险](#动作风险)、受[暂缓推进](game-bridge.md#看点与暂缓推进)约束；选择类动作仍一次一步并经决策点。
- 收到新目标、决策点打开、画面出现不是由动作引起的变化（如弹窗）或真人接管时，未执行的步骤立即作废。

当前目标的完成条件与超时由 planner 给出，见[规划](narrative-planner.md#规划)；超时即报 planner 重新规划，并计入[卡住](narrative-planner.md#坏结局与重来)。

标为 `completion_by_agent` 的目标接受附短证据的 `goal_judgment`。策略按调用时的目标代次、原帧号和变换版本绑定判断，完成判断与输入及开启决策点互斥。控制器确认原观察仍与当前新鲜画面相符，并在回执前再核对会话、规划器、目标和暂停状态。确定性条件使用[独立新帧核验](#子目标与终局)。达到步数上限后仍可核对完成条件，动作继续受步数上限约束。

## 定位与吸附

智能体给出的点击坐标须吸附到附近的 OCR 识别框或界面元素框（[感知](perception.md#界面元素检测)）上，且其文字或外观与目标描述相符，才算找到（GR-13、GR-24）。

| 定位结果 | 处理 |
| --- | --- |
| 找到 | 核对风险后执行 |
| 不存在、有歧义、已过期 | 不执行，以新帧重新调用智能体 |
| 证据不足 | 裁剪放大再问一次，仍不足即上报 |

**按坐标执行**（GR-24）：推进类与导航类动作在没有可吸附目标时可按坐标执行，条件是：

- 画面类型已知（以签名为准，见[画面类型](#画面类型)）且不是[危险画面](#动作风险)；
- 落点附近的小区域先做一次 OCR，核对禁用词；
- 执行后核验预期效果，未达到即不再按该坐标重试，改以新帧重新调用智能体。

按坐标执行的次数与结果计入[离线回放基准](offline-tools.md#离线回放基准)的统计。选择类只能吸附到可核验的目标上。不引入区域重排定位模型。

点击目标可在 `text` 中提供完整源行，在 `phrase` 中指定行内词项，并在 `roi` 中给出已标定的区域。点选前在该区域内确认完整源行唯一，且词项在该行内唯一。比较文字时统一大小写、宽度和连续空白，保留词界及组合附标的完整性。按字符宽度估算小框时计入行末标点的可见宽度，也可取已有的字符级识别框。小框须在原行框内，随后在同一帧上限时复读一次。两次 OCR 均须达到置信度门槛，复读须得到一个与词项精确相符的水平识别框，点击取该框中心。风险检查使用完整源行。证据不符、过期或余量不足即拒绝，模型坐标和估算框都不用于提交。

水平证据取自 OCR 拉平前的检测四边形。上下边偏离水平各至多 2°，两端高差各至多为较短侧边竖直投影的五分之一，两侧边各允许偏离竖直至多 2°。同一合并框的各段还须核对原始底边，两端的最大高差至多为原始分段中最大行高的五分之一。需要旋转裁片的竖框不参与词项定位。

## 动作分类与重发

| 类别 | 例子 | 效果不明时 |
| --- | --- | --- |
| 推进类 | 推进对白 | 等过动画时间、确认文字未变且未进入过场后，最多重发一次 |
| 导航类 | 打开菜单、返回、关闭 | 同推进类 |
| 选择类 | 选项、出示证据、指认 | 从不自动重发，上报结果未知并重新识别 |

暂缓推进有效时不执行推进类与导航类动作，选择类与计时决策不受影响。

## 决策点

- 识别到选择画面时生成决策点：选项文字、编号与实例号，连同 planner 的[候选](narrative-planner.md#规划)经[游戏桥](game-bridge.md#决策点)交给 Bellis。
- 智能体须输出“开决策点”而不是直接点选；点击落在选择区域内即拒绝并改开决策点。
- 执行 `decision.resolve` 前在新帧上重新定位并核对实例。
- 有计时的选项在截止前留出定位与执行的余量；到余量线仍未收到决定，即执行排第一的候选（Bellis D-07）。
- 行内词项触发无计时决策时，提示保留完整源行，选项显示词项。决策实例包含原 ROI、完整源行和词项。执行前在变换版本一致的新帧上按[定位与吸附](#定位与吸附)复核，检查决策实例和执行余量。计时滚动文本中的词项选择仍为 `unsupported`。

适配包声明的选项和计时 ROI 用于同帧核对。打开后继续读取新帧的倒计时，按采集时刻换算的截止只会缩短。操作员决定按主机收到的时刻与当前余量线比较。较短的截止使迟到的决定失效。候选就绪或截止缩短时用同一决策点编号更新控制台。

拆分授权目标期间可预览签名确认的计时选择，并继续读取倒计时和更新候选。执行需要规划器恢复到可执行状态，仍在当前画面重定位和核对。缺少可信计时、余量线没有已验证候选或决策实例改变时撤回。

截止约束输入提交与执行。实时核的已执行回执记录输入时刻，控制器另行核验画面效果。结果帧在截止后才稳定时，须在执行后、截止前已观察到同一目的画面的签名，才确认选择效果。结果未知时关闭决策点并进入[未决隔离](game-bridge.md#动作尝试与未决结案)。

## 重来入口

按 [GR-15](narrative-planner.md#坏结局与重来)，控制器在签名确认的坏结局画面等待。收到该画面出现后的新授权目标，且规划器报告 `restarting` 时，从适配包的 [`restarts` 声明](game-adapter.md#风险收紧与决策区域)读取唯一入口，在稳定的新鲜帧上核对 ROI 与精确文字。每个授权代次至多向实时核提交一次，结果按适配包声明的签名核验。该动作须满足同样的禁用词、静态禁区、窗口与操作员许可。

## 动作风险

（GR-21）动作按画面类型分三个等级，缺省按[通用画面类型](perception.md#画面状态)写一次，游戏适配包按本游戏的画面映射并只能收紧：

| 等级 | 范围 | 处理 |
| --- | --- | --- |
| 禁止 | 充值、真钱购买、平台内置界面中的购买确认；账号与安全设置；聊天、好友、举报、发帖等对外发言，联机游戏的快捷聊天与表情按钮；进入有真人玩家的联机 | 一律拒绝；需要时由操作员按[接管](realtime-core.md#接管与急停)手动操作 |
| 不可逆 | 出售或销毁物品、覆盖存档、删除角色、确认消耗大量游戏内资源 | 只能经决策点 |
| 普通 | 其余 | 照常执行 |

消耗付费货币缺省为禁止，适配包可降为不可逆，须经操作员批准。统一动作空间没有输入文字的动作。

四道互相独立的防线，任何一道拦下即拒绝：

1. **画面类型限制**：适配包为商店、充值、抽卡确认、设置与账号等危险画面写画面签名。危险签名命中后只允许白名单中的关闭或返回。未知画面依[限定导航](#动态画面的定位与准入)处理。
2. **目标文字检查**：吸附到 OCR 识别框后核对其文字，命中禁用词（充值、购买、支付、价格符号与金额格式、删除、举报等，适配包的词表加一份通用词表）即拒绝；命中不可逆即改开决策点。
3. **静态禁区**：实时核在白名单之外强制执行适配包声明的不论画面都不能点的区域（[实时核](realtime-core.md#输入策略)）。
4. **窗口与操作员前置条件**：实时核只向游戏窗口注入，独立的付款窗口本来点不到；开播前由操作员确认适配包声明的前置条件（如关闭平台内置界面、游戏账号不开免密支付、不存一键付款、打开消费上限），见[游戏桥](game-bridge.md#开播前置条件)。

被拒的动作记入日志与健康上报，智能体换方案；同一画面多次被拒按[卡住](narrative-planner.md#坏结局与重来)上报。该计数是[游戏桥风险观测](game-bridge.md#风险观测与恢复)的来源。

## 模式仲裁

（GR-26）由确定性规则决定当前的控制产出者是逐步控制器还是某个连续策略后端：

- 输入为画面类型（以签名判出的为准，见[画面类型](#画面类型)）与当前目标，规则写在游戏适配包；认不出画面类型时留在逐步模式。
- 仲裁器属于主进程关键平面；切换即更换控制产出者，先释放输入，按[控制产出者的 QUIESCING](plugin-kernel.md#控制产出者) 进行，切换与原因记入健康上报。
- 不调用 LLM。剧情游戏只有逐步模式，仲裁器始终选逐步控制器。
- **守卫**（原神阶段）：仲裁器持续监督连续模式，目标超时、连续核验失败、画面类型变为非即时玩法或未知、画面状态不健康时收回控制，切回逐步模式并上报原因；守卫条件写在适配包的仲裁规则里，缺省按通用画面类型。

## 策略后端契约

（GR-33）每个策略后端提供 `policy@1`，逐步控制器是第一个实现，连续策略后端与 VLA 以后接同一份契约：

| 项 | 内容 |
| --- | --- |
| 输入 | 帧环的只读句柄、[画面状态](perception.md#画面状态)、OCR 结果、当前目标与完成条件、笔记摘要、最近几步的动作与结果 |
| 输出 | 逐步模式：一个单步提议，附目标描述、预期效果与置信度；连续模式：一个[动作块](core-protocol.md#动作块)。动作类型取自统一动作空间，含预留的“调用技能”（[技能](#技能)） |
| 生命周期 | 作为控制产出者激活与停用，停用走[控制产出者的 QUIESCING](plugin-kernel.md#控制产出者) |
| 遥测 | 按后端记录每步时延、模型调用、拒绝与核验结果，供[离线回放基准](offline-tools.md#离线回放基准)按配置替换后端对比 |

逐步后端实现 `Policy.propose(PolicyInput) -> Plan`。同一个可选的 `planner@1` 通过 `PlannerPort` 给出当前目标、笔记、暂停状态与 `planning`、`restarting` 状态。控制器按认证会话和目标指令序号调用 `submit_goal`，同一目标代次的步数和结局在控制产出者重建时保留。候选排序按会话与决策实例读取。planner 接收按会话编号和实例编号关联的决策事件与带目标代次的进度事件。视觉观察经 `scene@1` 接受后以原始帧号、变换版本和采集时刻发出回执。

使用中的 planner 失效或更换时废弃未提交的计划与决策，暂停控制。收到认证会话的新目标、交给可用的 planner 并读到其恢复状态后才重新规划。独立会话没有使用 planner 时，操作员目标仍直接交给当前策略。

连续模式的输入节奏（帧率、时序）在 GS-08 之前只预留字段。

## 本地遥测

普通插件 `telemetry` 提供可选服务 `telemetry@1`，按 Bellis R-21 写本机 OTLP JSONL。[语义连接](game-bridge.md)的消费方保存接收消息时的连接代次、目标或决策标识与 `traceparent`，随后用该上下文记录因这条消息而产生的 span。使用合法的 W3C `00` 父标识时沿用其 trace ID，缺少有效父标识时另开根 span。动作发布时核对 `traceparent` 对应当前服务仍在记录的步骤，校验失败时沿用该动作的有效父上下文。目标、决策或连接失效时用原代次和对应标识关闭活动 span，迟到的完成回调对已关闭的句柄无效。

| 入口 | span | 写出的属性 |
| --- | --- | --- |
| `command_received` | `game.command` | `bellis.game.command` 取 `goal.submit` 或 `decision.resolve`，结局取 `accepted` 或 `rejected` |
| `step` | `game.step` | `bellis.game.category` 取 `advance`、`navigate` 或 `select`，结局取 `verified`、`no-effect` 或 `rejected` |
| `decision_opened` | `game.decision` | 决策实例首次开放时记录，`bellis.game.timing` 取 `timed` 或 `untimed`，结局取 `opened` 或 `rejected` |

`bellis.game.outcome` 也可取 `unknown`、`cancelled` 或 `invalidated`。每次实际尝试在定位前捕获上下文并开始计时，定位失败也结案。转入等待决策的提议以 `cancelled` 结束。步骤按实际到达的顺序记录 `game.step.located`、`game.step.submitted`、`game.step.executed` 和 `game.step.effect_checked`，各阶段至多一次。`submitted` 以实时核确认接收为准，`executed` 以匹配且合时的 `Executed` 回执为准，`effect_checked` 在效果核验返回时记录。同一决策的更新沿用首次开放的上下文，默认选择从该决策的开放 span 延续，收到决定的选择从对应的命令 span 延续。写出的属性和值限于表中枚举与固定的服务名，事件只有名字与时刻。连接代次与目标、决策标识只用于本进程的关联。耗时由单调时钟计算，导出时刻以 Unix 纳秒表示。

新帧复核切到默认选择时，同一次步骤尝试改接决策开放 span，保留已测的定位起点。提交入口固定回执截止，接受匹配的 `Executed` 后固定核验截止。两阶段的遥测回调在回执等待结束后执行，事件保留实际阶段时刻。

在 `supervise` 的 profile 中启用 `telemetry` 条目并将本机绝对路径填入 `config.directory`。`--telemetry-dir <绝对路径>` 可启用该条目并覆盖目录，profile 未列出该条目时可用该参数直接启用。守护线程分批追加，每行一个 `ExportTraceServiceRequest`，文件名区分进程实例。批写间隔 `flush_interval_ms` 缺省 100 毫秒，队列 `max_queue` 缺省 1024 条，满时丢最旧的记录；活动 span 上限 `max_active_spans` 缺省 128 条，满时跳过新 span。达到 `max_file_bytes`（缺省 8 MiB）或 `max_file_age_ms`（缺省 1 小时）就轮转，每个进程实例保留最新的 `max_files` 个文件（缺省 24）。写入失败丢弃该批。停用回调关闭活动 span 并请求排空后即返回，守护线程只在 250 毫秒内领取待写批次，剩余记录丢弃。宿主完成撤权和输入释放并停止实时核后，在同一时限内等待排空。遥测回调后继续执行原有授权、时限和帧复核。

## 技能

（GR-34）普通插件 `skills@1`，游戏无关的多步过程：关闭弹窗、在菜单中找到某段文字并进入、滚动列表直到出现某项、返回主界面。

- 每个技能带前置与后置条件；内部每步仍走[定位与吸附](#定位与吸附)、[动作风险](#动作风险)与效果核验，展开为原子动作后才到实时核，实时核只见原子动作。
- 智能体通过统一动作空间的“调用技能”使用技能；技能不能绕过决策点与四道防线，选择类动作仍一次一步。
- 技能是代码，进版本库，由[合成游戏](offline-tools.md#合成游戏)与回放基准验证。
- 在首个具体需要出现时建：预计是原神的菜单与背包；《魔女审判》在 G2 出现重复的导航序列则提前。此前只在[策略后端契约](#策略后端契约)里预留动作类型。
