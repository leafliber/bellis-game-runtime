# 离线工具

不进直播进程的本机工具：合成游戏夹具、只读运行、录制、标定、经验审核与离线回放基准，以及并行的 VLA 研究工具；另有模型制品的获取（[模型制品](game-adapter.md#模型制品)）与 GS-04 的评测（[OCR](perception.md#gs-04-的评测工具)）。代码放在 `tools/`。产出的制品经批准才上线；从游戏派生的数据只存本地数据目录。G0 实现合成游戏，G1 实现只读运行、录制与回放基准的样本格式，G2 起实现标定、回放基准与经验审核。

## 职责

- 提供不受任何游戏条款约束的合成游戏，供自动测试、真机闭环与通用度基准使用。
- 维护者手动游玩时只读地运行感知插件，在终端里显示它们的结果。
- 在本机录制帧、游戏声音与标注，供评测与回放。
- 帮助操作员标定快路径签名、审核经验快路径候选。
- 以回放量化每次改动的影响。

## 不负责

- **训练《魔女审判》的任何模型。** 只评测，不训练（[合规](../compliance.md)）。
- **直播路径。** 工具的结果写入不入库的报告，不直接改变运行中的配置。

## 合成游戏

（GR-30）仓库内的一个小游戏，作为测试夹具，不受任何游戏条款约束。代码是 uv 工作区成员 `tools/synthetic-game/`，发行名 `synthetic-game`，导入名 `synthetic_game`。

- **核心**：无窗口的状态机 `SyntheticGame` 加 Pillow 渲染到像素缓冲；画面含对话逐字显示、选项、计时选择、菜单、商店、弹窗、播片与坏结局。时钟可注入：同样的输入序列在同样的时钟读数下得到同样的状态与同样的帧，测试用手动时钟推进，不真睡。分辨率（缺省 1280×720，可在 320×180 到 7680×4320 之间）、文字速度（每秒显示的字数，缺省 30）、计时选择的时长（缺省 5 秒）与播片的时长（缺省 4 秒）可配置。
- **真机**：tkinter 外壳把缓冲显示成真实窗口，经 WGC 采集与 SendInput 驱动，跑完整闭环。
- **自动测试**：缓冲经假显示面喂给[假采集源](realtime-core.md#假采集源)，假输入后端的动作回送状态机，跑除采集与注入外的全链路；Windows 真机与 Linux 容器都运行。
- **适配包**：`games/synthetic-game/`（[格式](game-adapter.md#格式)），是声明格式的第一个样例。窗口识别按下文的[窗口外壳](#窗口外壳)，期望分辨率取缺省的 1280×720；ROI 是整个客户区，以及 `layout.py` 中对话背景的钟楼、名字栏、对白文字、继续标记、选项提问、选项按钮（三个按钮的外接矩形）、计时条、菜单的三个按钮、商店列表与“离开”、弹窗与坏结局的文字和按钮的矩形除以 1280×720；画面类型映射即下表第二列，播片除外（它不是声明的画面，见下一条）；语言核对的固定文字一层用标题菜单三个按钮的文字；[对白框](game-adapter.md#对白框)在对话画面上，名字栏与对白文字两个 ROI 加继续标记的签名。快路径可整体关闭，用作通用视觉智能体的回归基准。
- **画面签名**：每个画面一个，以底色与固定面板上的像素检查为主（颜色取自 `render.py`）。对话的底色随剧情节点变，改看钟楼的钟面，另以钟面作锚点；继续标记的签名是对话签名的三处像素检查加上继续标记三角形里的一点，与对话的签名同级、指向对话，一句显示完时才命中；计时选择比选项多一处计时条上的点（已走与未走的颜色都在容差内），叠加优先级更高；标题菜单与坏结局各另有一项固定文字（“开始”“重来”），没有 OCR 时这两种画面不可判。弹窗不是画面，弹窗压暗整个画面，显示时不命中任何签名。播片也不是画面，由 `scene@1` 按持续整屏的动态识别（[变化与稳定](perception.md#变化与稳定)）；动画与字幕的颜色避开各签名所看的颜色，播片中不命中任何签名。锚点模板不进版本库：`synthetic_game.anchors` 从缺省分辨率的渲染裁出钟面，编码成不压缩的 PNG（同样的像素在任何平台上得到同样的字节与摘要），测试写进临时的本地数据目录。
- 它只能证明链路通，不能代替真机验收（Bellis D-11）。

### 画面与转换

台词是为夹具原创的简短中文，画面上出现的全部文字与剧情图都定义在 `story.py`。

| 画面 | 通用画面类型 | 进入 | 操作与去向 |
| --- | --- | --- | --- |
| 标题菜单 | 菜单 | 启动、剧情读完、离开商店 | “开始”进入开场对话；“商店”进入商店；“说明”弹出说明 |
| 对话 | 对话 | 开始、选项、重来 | 逐字显示；推进时本句未显示完就先补全，已显示完就进入下一句；最后一句之后进入下一节点，个别节点先弹窗 |
| 选项 | 选择 | 开场对话读完、播片放完 | 三个选项：进入地下的对话、插曲对话（读完放播片，放完回到本选项）、坏结局 |
| 计时选择 | 计时选择 | 地下对话之后的弹窗关闭 | 两个选项：坏结局、结尾对话；画面有倒计时条与剩余秒数，到截止时刻进入超时的坏结局 |
| 商店 | 商店 | 菜单 | 8 件物品，每屏 4 行，可滚动；点击一行即购买，已拥有的不变，金币不足时弹窗；“离开”回到菜单 |
| 播片 | 过场 | 插曲对话读完 | 整屏的动画（程序生成的色块与图形，每帧都变）放 `cutscene_seconds`（缺省 4 秒），对白文字的位置上依次显示两句字幕，各占播片后 5/8 的一半（缺省为 1.5–2.75 秒与 2.75–4 秒：`scene@1` 约 2 秒才判出播片，两句在此之后都还看得见）；播片中的输入都忽略，放完回到选项 |
| 坏结局 | 坏结局 | 选错、超时 | “重来”回到开场对话的第一句 |
| 弹窗 | 无，见下 | 菜单的“说明”、商店金币不足、地下对话读完 | 模态，只有“确定”可点；关闭后回到底下的画面，或进入预定的下一节点 |

- 结尾对话读完加 30 金币后回到菜单。金币初始 50，金币与已购物品跨画面保留，其余状态进入节点时重置。
- **逐字显示**：已显示的字数为（当前时刻 − 本句开始时刻）× 文字速度，向下取整。
- **计时**：计时选择从进入时开始计时，弹窗显示期间不计时。到截止时刻（含）即超时，转换按截止时刻本身发生，与何时被观察无关；截止之后才到达的输入落在坏结局上，不会选中选项。
- **与通用画面类型的映射**：上表第二列，取自[画面状态](perception.md#画面状态)的通用分类，真值里的画面类型直接用分类的名称。通用分类里没有弹窗，弹窗表示为叠加层：真值的画面类型仍是底下那个画面的，另以叠加层给出弹窗文字。合成游戏不产生其余通用类型（设置、存读档、加载、即时玩法、地图、背包、卡住、未知）。

### 输入与真值

输入用本包自己的小类型（`synthetic_game.inputs`），对应[统一动作空间](../architecture.md#控制的组织)里会到实时核的部分，不依赖核协议；假输入后端与窗口外壳各自把动作转换成它们。坐标一律是客户区的物理像素，原点在客户区左上角。

| 输入 | 字段 | 规则 |
| --- | --- | --- |
| 点击 `Click` | 坐标，鼠标键（左、右、中） | 只有左键触发目标；目标矩形含左边与上边、不含右边与下边；有弹窗时弹窗之外的点击都算未命中 |
| 短按 `Press` | 键：回车、空格、Esc、上、下 | 上下移动光标（菜单与选项循环；商店不循环，列表随光标滚动）；回车与空格触发光标所在的目标；Esc 关闭弹窗、离开商店 |
| 滚动 `Scroll` | 坐标，格数（正数向上，与 Windows 滚轮的符号一致） | 只在商店列表内有效，一格一行，光标留在可见范围内 |

`handle` 返回这个输入的效果：命中（点中并触发了某个目标）、未命中、按键（被当前画面处理）、滚动、忽略（非左键点击、当前画面没有绑定的键、列表之外或有弹窗时的滚动、播片中的任何输入），以及被触发或选中的目标与状态是否改变。

`truth` 是只给测试与假后端断言用的真值接口；运行时只能从像素感知画面，不能读它。它给出：通用画面类型、剧情节点、叠加的弹窗、当前可点的目标（标识、矩形与文字，有弹窗时只有弹窗上的目标）、键盘光标所在的目标、画面的主要文字及已显示的部分、计时剩余、金币、已购物品与上一个输入的效果。点击是否命中，以点击坐标、目标矩形与效果三者对照证明。播片时没有可点的目标，主要文字为当前的字幕，另给出播片的开始与结束时刻。

| 目标 | 标识 |
| --- | --- |
| 菜单项 | `menu.start`、`menu.shop`、`menu.help` |
| 对话框 | `dialogue.box` |
| 选项 | `choice.<序号>`，从 0 起 |
| 商店的行与离开 | `shop.item.<物品序号>`（只有可见的行）、`shop.leave` |
| 弹窗的确定 | `popup.ok` |
| 坏结局的重来 | `ending.retry` |

### 渲染

- `frame` 返回帧：像素、宽、高与帧号。像素为 BGRA8，自上而下逐行排列，行跨度为宽乘 4，alpha 恒为 255，与[帧环](core-protocol.md#帧环与音频环)一致。
- 帧号从 1 起，画面内容变化时才加一；内容没变时返回同一帧，同样的画面渲染出同样的像素。
- 设计稿按 1280×720，在横纵两个方向按分辨率分别缩放。点击判定与渲染共用同一组矩形，画出来的按钮就是能点中的区域。
- 文字固定用 Pillow 的基本排版引擎，不随系统是否装有 raqm 而变。

### 字体

- **来源**：Noto Sans SC Regular 2.004，取自官方仓库 notofonts/noto-cjk 发布 Sans2.004 的标签下的 `Sans/SubsetOTF/SC/NotoSansSC-Regular.otf` 与 `LICENSE`，与该发布的附件 `18_NotoSansSC.zip` 中的同名文件逐字节相同；URL 与 SHA-256 写死在 `font_subset.py`。
- **取字**：`story.py` 里的全部文字、ASCII 可打印字符与常用中文标点；不保留 OpenType 排版特性。
- **命名**：原字体的版权声明与许可都没有声明 Reserved Font Name，OFL 不强制修改版改名；子集仍改名为 Synthetic Game Sans SC（PostScript 名 `SyntheticGameSansSC-Regular`），不让这个子集以 Noto（Google 的商标）的名字出现。版权、商标、作者与许可等名称记录原样保留。原字体一旦声明了 Reserved Font Name，脚本即失败，须重新核对命名。
- **入库**：`src/synthetic_game/fonts/` 下的子集、OFL 全文 `OFL.txt`（与上游 `LICENSE` 逐字节相同）与来源说明 `SOURCE.toml`（URL、版本、原文件与子集的 SHA-256）。原字体不入库。
- **重新生成**：改了台词后在仓库根目录运行 `uv run python -m synthetic_game.font_subset`。脚本把原字体与许可下载到临时目录并核对 SHA-256，已有原文件时可用 `--source-dir` 指定（同样核对）；同样的原字体与台词总是得到逐字节相同的子集。检查核对子集的 cmap 恰好是所需的字，改了台词而没重新生成子集即失败。fontTools 是开发依赖，只有这个脚本与字体测试用到它。

### 窗口外壳

- **入口**：`uv run synthetic-game`，可加 `--width`、`--height`、`--text-cps`、`--choice-seconds`、`--cutscene-seconds`、`--redraw-hz`、`--autoplay`。
- **自动推进**：`--autoplay <秒>` 让外壳每隔这么久自己处理一次回车短按（直接交给状态机，不经系统输入），从标题菜单进入对话、逐句推进，画面持续变化而不需要任何真实输入；供录制的真机测试使用。
- **窗口识别**：标题 `Bellis Synthetic Game`；Win32 窗口类 `TkTopLevel`，由 Tk 固定、不能配置，所有 Tk 程序都相同，须与标题一起用；拥有窗口的进程是 uv 管理的 `python.exe`，`synthetic-game.exe` 只是启动它的启动器。Tk 类名为 `BellisSyntheticGame`，即 X11 的 WM_CLASS。
- **DPI 与尺寸**：Windows 上建窗之前把进程声明为按显示器感知 DPI v2，客户区就是配置分辨率的物理像素，WGC 采到的尺寸等于缓冲尺寸；窗口不能缩放。客户区里只有一个显示帧的标签，原点与客户区左上角重合。
- **事件**：鼠标左、中、右键按下即转成点击；滚轮增量累积到 120 为一格转成滚动，X11 的 4、5 号键各为一格；Return、space、Escape、Up、Down（含小键盘的回车与上下）转成短按，其它键丢弃。真实的鼠标键盘事件因此能经 SendInput 驱动它。
- **持续重画**：外壳按固定频率重画窗口，缺省 30 Hz，`--redraw-hz` 可改（大于 0、不超过 1000）；画面内容没变也重画。WGC 只在窗口内容变化时出帧，静止的画面不重画就没有新帧、帧龄一直增长；真实游戏一般也每帧都在绘制。每次重画取当前帧，把它重新贴进显示帧的标签。重画排在固定的时刻上，不随每次重画的耗时漂移，落后超过一个周期时不追赶；输入处理完、画面变了即刻更新，不等下一次重画。
- **实测**（Windows 11 真机，1280×720，停在静止的标题菜单，`capture-probe` 采 10 秒）：不重画时只出 1 帧；30 Hz 时 29.7 fps；60 Hz 时 49.8 fps，没达到 60 的原因未查。
- 没有 tk 或没有显示的环境（如 Linux 容器）里，外壳的测试跳过。

## 只读运行

维护者手动游玩时，按适配包拉起实时核与感知插件，在终端里实时显示画面判别、配音忙闲与剧情记录，可同时录制；不发任何输入，不连 Bellis。代码在 `runtime/src/game_runtime/observe/`。它与[录制工具](#录制工具)是同一个实时运行（`LiveSession` 与同一个运行循环）的两种用法：`record` 只打印录制的状态行，`observe` 另显示感知的结果与结束时的摘要，可以不录制。G1 实现。

`uv run observe <适配包 id>`，可加 `--record`（同时录制）、`--name`（录制的名字，只与 `--record` 一起用）、`--status-interval`（状态行的间隔，缺省 5 秒），以及与录制工具含义相同的 `--seconds`、`--max-rate`、`--idle-interval`、`--max-size`、`--core`、`--data-dir`、`--verbose`：

- 实时核、帧环与音频环同录制工具：按窗口识别规则设定采集与音频目标，帧环按期望分辨率定大小；不给测试设备，内核的 `CoreControl` 拒绝一切提交。
- **插件**：录制时的同一组感知插件（[M0 回放](#m0-回放)的“插件”），另加只读运行自己的 `observer`（[下文](#observer-插件)）。不录制时不运行写文件的 `results`，剧情记录写进本地数据目录的 `narrative/<适配包 id>.sqlite3`，即实时运行的剧情记录（[存储](narrative-planner.md#存储)）。
- **激活**：不录制时插件不必全部激活，没激活的显示状态与原因，其余照常运行。例如没有 OCR 模型时 `ocr@1` 激活失败、`narrative@1` 停在 WAITING，签名的固定文字项不可判，配音检测照常。加 `--record` 时同录制工具：插件没有全部激活即不开始，因为 `live/` 的输出要与回放比对。
- **录制**：加 `--record` 时的录制目录、配额、`live/` 的输出与收尾都与 `uv run record` 相同，录制的元数据不记它是由哪个命令录下的。不加时不建录制目录，不核对配额。

### observer 插件

普通插件 `observer`，只读：不提供服务，不申请权限，不写任何文件。

- **清单**：依赖 `game-adapter@1` 与 `scene@1`，可选依赖 `voice-activity@1`、`narrative@1` 与 `ocr@1`。
- **激活**：订阅 `scene@1`；可选的三项当即探测一次，之后每 0.5 秒再探测，出现了（如退避重试后才激活）就订阅，换了或停用了就退订。收到的结果交给宿主显示与统计（`ObserveHub`），语言核对见[下文](#只读运行的语言核对)。不录制时它把 `narrative@1` 交给宿主（`ResultsHub`，录制时由 `results` 交），宿主在停插件内核之前等剧情记录处理完积压的更新。
- **停用**：退订，取消在途的语言核对，记下剧情记录此刻的各句、范围、播片段与中断供摘要使用。

### 显示

全部写到 stdout，每个事件一行，带距命令开始的时刻（采集时钟），不改写已输出的行，重定向到文件也可读；不用 TUI 库。

- **开始**：适配包、帧环尺寸、是否录制与录制目录；各插件的状态，没激活的写明原因；不运行 `narrative@1` 时写明原因（对白框没有声明或尚未标定）；适配包尚未标定的项（`uncalibrated()`）；`scene@1` 的问题（模板缺失等）；语言核对的两层各怎样核对，或为什么不核对（不运行剧情记录、文字系统不受支持、没有声明固定文字）。
- **状态行**，每 `--status-interval` 秒一行：画面与声音的采集状态，接纳帧率与帧环帧率，积压（定序帧源里 `scene@1` 还没读的帧数、剧情记录还没处理的更新个数）与积压超限的次数，当前画面的判别结果与稳定性，配音状态，剧情记录的句数；录制时另加帧数、块数与体积。
- **画面**：判别结果变了即一行：结果为画面时是哪个画面，歧义时是哪几个画面，其余写结果，不可判与停用附说明；带当时的稳定性与帧号。只看结果、画面与歧义的画面，说明变了不另起一行；稳定性的变化不单独显示，见状态行。
- **配音**：`voice-activity@1` 的每条变化一行：忙、闲，或未知与原因，带估计的转换时刻。
- **播片**：剧情记录的每个[播片段](narrative-planner.md#播片段)开始与结束各一行，带编号；结束的一行带播片段的时长与其中的句数。播片中读到的字幕照常按剧情记录显示，行里标出播片段编号。
- **剧情记录**：每句在以下几处各一行，带出现编号、说话人、文字、完整度与修订号（适配包有多个对白框时另带画面）：出现（第一次读到）、判为完整、判为完整之后又被修订（回到部分，或文字、说话人变了）、结束（完整，或缺口与读到的文字）。逐字显示中途的修订不逐个显示，修订号写在下一次显示的行里。当前修订里有低置信度的行时，在行末列出 ROI、文字与置信度。剧情记录在 OCR 之后才处理完，它的行可能排在时刻更晚的画面行之后；行首的时刻都是采集时刻。
- **插件**：开始之后状态或原因变了即一行（如退避重试）；进入 LOADING 与停止期间的变化不显示，开始时的状态见开始的几行。

### 只读运行的语言核对

`observer` 按[语言核对](game-adapter.md#语言核对)的两层核对（[语言核对的执行](perception.md#语言核对的执行)）：

- **文字系统**：剧情记录每结束一句完整的句子，以 `check_script` 核对它的文字；没有可数的字母（无从判断）的句子不计。前 3 句判断了的句子都相符即显示相符，任一句不符即显示不符并列出这句的出现编号、文字与比例；有了结果之后的句子不再核对。此刻没有 `ocr@1` 时这一句不核对、不计。不需要标定。
- **固定文字**：声明了固定文字的画面每次出现，在它的第一个已稳定帧上以 `check_language` 核对一次。一次出现从判出这个画面起，到判出另一个画面止；其间的不命中、不可判、歧义与停用（弹窗、淡入淡出）不算离开。同一时刻至多一次核对在途，后来的排队。结果：相符（各项都相符）；不符，列出不符的项（ROI、应有的文字、读出的文字）；出错（OCR 出错或此刻不可用）。列表为空时不做这一层。
- 每次的结果都显示一行，另记日志：相符为 INFO，不符与出错为 WARNING。
- G1 只报告，不符时照常运行；G2 起由逐步控制据此不进入自动游玩并上报操作员（[内容](game-adapter.md#内容)）。

### 尚未标定时

尚未标定的项不出结果，只显示原因，其余照常运行（[尚未标定](game-adapter.md#尚未标定)）：没有组成项的签名不参与判别，全部签名都尚未标定时画面一直是不命中；对白框尚未标定时不运行 `narrative@1`，也就没有文字系统一层的语言核对与播片段；固定文字为空时不做固定文字一层。只读运行仍可同时录制，录下的帧与声音供标定使用。

### 停止与摘要

- **停止**：同录制工具：按回车或 Ctrl+C、`--seconds` 到时、实时核退出、接纳出错；录制时另有录满配额与写入出错。依次关闭定序帧源、等 `scene@1` 读完已接纳的帧、等剧情记录处理完积压的更新（各至多 30 秒）、停插件内核、录制时停录声音、按 R-06 停实时核、录制时写完录制，最后依次打印摘要、录制的结果与实时核停在哪一步。实时核在自己的进程组里，Ctrl+C 只到主进程；收尾期间再按 Ctrl+C 即强制退出。
- **摘要**：
  - 剧情记录：句数，完整、部分（停止时还在显示）与缺口的个数，剧情范围与中断的个数，播片段的个数与总时长（停止时还没结束的算到最后一个在播片中的帧）；不运行时写明原因。
  - 画面判别：各结果（画面按画面分开）的帧数与时长占比；时长按采集时刻，每帧算到下一帧为止。
  - 配音：忙、闲与未知（按原因分开）的时长占比，从命令开始到停止。
  - 语言核对：文字系统一层的结果（相符、不符，或判断了几句还不到 3 句），不核对时写明原因；固定文字一层每个画面核对的次数与各结果的次数，没有核对过或没有声明时写明。
  - 录制：同录制工具结束时的几行，含录制目录。
- **退出码**：不能开始为 2（参数、适配包、配额）或 1（实时核或插件）；录制时同录制工具；不录制时按回车、Ctrl+C 或到时停止为 0，接纳出错或实时核退出为 1。

## 录制

把实时运行接纳的帧序列、游戏声音与标注录到本地数据目录，供标定、评测与 M0 回放。代码在 `runtime/src/game_runtime/recording/`（只读运行入口同时录制时在主进程里复用写入方，所以不放在 `tools/`）：样本格式的写入与读取、留存、导出、回放与命令行。G1 实现。

- 录制只存本地数据目录，不进版本库，按游戏分开；录制按该游戏的条款处理。《魔女审判》按 C-4（2026-11-01 允许）：只存本机，留存上限每款游戏 50 GB，超出时删最旧的录制；样本与 GS-04、GS-06、GS-07 共用。
- 留存上限取适配包合规声明的 `recording_quota_gb`，为 0 时录制工具拒绝运行（[留存](#留存)）。
- 游戏适配包的合规声明禁止时，示范记录器拒绝运行。

### 录制工具

`uv run record <适配包 id>`，可加 `--name`（录制的名字：字母、数字、`-`、`_`，至多 40 个）、`--seconds`（录这么久后停止）、`--max-rate` 与 `--idle-interval`（[接纳](perception.md#定序帧源)的参数）、`--max-size <宽>x<高>`（帧环的最大尺寸，缺省为适配包的期望分辨率）、`--record-only`、`--data-dir`（本地数据目录，缺省按[术语](../architecture.md#术语)）、`--core`（已编译的 `realtime-core`；缺省先以 cargo 编译 release 版）。它与 `uv run observe <适配包 id> --record` 是同一个实时运行，只是终端上不显示感知的结果（[只读运行](#只读运行)）：

- 按适配包的窗口识别规则设定采集目标与音频目标，帧环按期望分辨率定大小，经 `CoreLink` 拉起实时核。不发任何输入（不给测试设备，实时核没有许可源；内核的 `CoreControl` 拒绝一切提交），不连 Bellis。窗口比帧环大时帧写不进帧环，状态行里帧环的帧率为 0。
- 帧经[定序帧源](perception.md#定序帧源)进入录制，写入方是它的接收方，录下的就是接纳序列。声音由录制自己每 20 ms 读一次音频环里比已录的更新的全部块，先于插件开始，录下音频环的每一块。
- 插件内核里同时运行与回放相同的一组感知插件（[M0 回放](#m0-回放)的“插件”），它们的输出写进录制的 `live/`，供与回放比对。模型制品在本地数据目录里，没有时 `ocr@1` 与 `voice-activity@1` 激活失败，录制不开始（先 `uv run fetch-models`）；插件没有全部激活即不开始，也不建录制目录。`--record-only` 时只录制，不运行感知插件，`live/` 为空。
- 每 2 秒打印一行状态：画面与音频的采集状态、接纳帧率与帧环帧率、在途的编码、帧数与块数、体积与剩余配额、读者积压超限的次数。
- **停止**：按回车或 Ctrl+C、`--seconds` 到时、录满配额、实时核退出或写入出错。依次关闭定序帧源、等读者处理完已接纳的帧、等剧情记录处理完积压的更新（各至多 30 秒）、停插件内核、停录声音、按 R-06 停实时核，最后写完在途的编码、索引与元数据，打印实时核停在哪一步。实时核在自己的进程组里，控制台的 Ctrl+C 只到主进程（[非提权子进程](realtime-core.md#非提权子进程)）。收尾期间再按 Ctrl+C 即强制退出，录制停在 `recording` 状态，不完整。

### 样本格式

每段录制一个目录：`<本地数据目录>/recordings/<适配包 id>/<开始时刻>[-<名字>]/`。开始时刻是 UTC 的 `YYYYMMDDTHHMMSSZ`，目录名的顺序就是时间的顺序；同一秒里已有同名目录时加 `-2`、`-3`。

| 文件 | 内容 |
| --- | --- |
| `recording.json` | 元数据，见下 |
| `frames.jsonl` | 帧索引：每行一帧，按接纳的顺序 |
| `frames/<帧号>.png`、`frames/<帧号>.delta` | 关键帧与差分帧的像素，帧号补零到 8 位 |
| `audio.jsonl`、`audio.f32` | 块索引（每行一块，按块号）与样本值 |
| `annotations.json` | [标注](#标注)，创建时为空 |
| `live/` | 录制时实时运行的感知插件的输出，见 [M0 回放](#m0-回放)的“输出” |
| `replay/` | 最近一次 M0 回放的同样的输出 |

JSON 一律 UTF-8、LF 换行。以 `_ns` 结尾的时刻都是采集时钟（[时钟](realtime-core.md#时钟)）的纳秒读数，重启系统后不可比。

**帧索引**的每一行：

| 字段 | 含义 |
| --- | --- |
| `frame_number` | 帧环里的帧号，即实时运行时读者拿到的帧号；严格递增，没接纳的帧号空着 |
| `capture_ns`、`transform_version`、`width`、`height` | 同 `RingFrame` |
| `encoding` | `png`、`delta` 或 `same`，见下 |
| `file` | 像素文件相对录制目录的路径；`same` 为 null |
| `crc32` | 解码出的像素（BGRA8，行间无填充）的 CRC-32，回放与核对时校验 |

**像素的编码**，都无损：

| 编码 | 文件 | 解码 |
| --- | --- | --- |
| `png` | 关键帧：8 位 RGBA 的 PNG（OpenCV `imencode`，压缩级别 1），alpha 照原样保留 | 本身即完整的帧 |
| `delta` | 差分帧：与上一行的帧逐字节异或后的 BGRA8，以 zlib（RFC 1950，级别 1）压缩 | 解出上一行的帧，与它异或 |
| `same` | 没有文件：像素与上一行的帧相同 | 即上一行的帧 |

- 第一帧、尺寸变化后的第一帧，以及像素与上一帧不同、且距上一个定时关键帧的采集时刻不短于 5 秒的帧写成关键帧，所以解码任一帧至多回溯约 5 秒的差分；差分里变化的像素超过一半（切换画面、淡入淡出）时也写成关键帧。
- 编码在线程池里并行（缺省 `min(4, CPU 数)` 个线程），索引按接纳的顺序写；在途的帧至多为线程数的两倍，再多就让定序帧源等着，接纳帧率随之降下来。像素文件先写临时文件再改名，写完才进索引。
- **依据**：帧须无损，OCR 与签名的评测都要原像素。逐帧 PNG 在 2560×1440 上单线程每帧约 50–140 毫秒、0.1–3 MB（插画与照片约 2–3 MB，见[实测](#实测)），按每秒 10 帧录真实游戏的画面每分钟可达 1–2 GB，50 GB 只够半小时；剧情游戏的画面大多只有对白框在变，与上一帧异或后多为 0，zlib 压缩后每帧几十 KB，异或加压缩约 20 毫秒。关键帧用 PNG，查看与导出不必转换。zlib 与 PNG 都来自已有的依赖（标准库与 OpenCV），不加依赖。

**音频**：`audio.f32` 依次存每一块的样本值（F32 小端、各声道交错），`audio.jsonl` 每行一块：`block_number`、`capture_ns`、`sample_count`、`discontinuity`（实时核标的不连续）与 `offset`（在 `audio.f32` 里的字节偏移）。录下音频环的每一块；块号有空缺说明录制落后于音频环、其间的块被覆盖，元数据里计数。不压缩，48 kHz 立体声每分钟约 23 MB。

**元数据** `recording.json`：开始录制时写入，`state` 为 `recording`；收尾时改写为 `complete`，写入出错时为 `failed`。每次都先写临时文件再改名。

| 字段 | 含义 |
| --- | --- |
| `format` | 样本格式的版本，现在为 1；读取方只接受认识的版本 |
| `state` | `recording`（正在录，或异常中断而不完整）、`complete`、`failed` |
| `name`、`started_at`、`ended_at` | 名字；开始与结束的 UTC 时刻（ISO 8601） |
| `stop_reason` | `enter`、`interrupt`、`seconds`、`quota`、`core-exited`（实时核自己退出了）、`error`，没停为 null |
| `game` | 适配包的 `id`、`name`、`version`、`adapter.toml` 的 SHA-256 与期望分辨率 |
| `tool` | 本仓库的提交与工作树有无改动（取自 git，取不到为 null） |
| `admission` | 接纳的参数 `max_rate`、`idle_interval` 与 `backlog` |
| `frames` | 帧数、关键帧数、像素文件的字节数、第一帧与最后一帧的采集时刻 |
| `audio` | 采样率、声道数、样本格式 `f32le`、块数、块号的空缺数、字节数、第一块与最后一块的采集时刻；没有配置音频为 null |
| `reader_overflows` | 定序帧源积压超限的次数；不为 0 时实时结果与回放不一致 |

### 标注

`annotations.json` 在标定与评测时由工具或手工写入，`game_runtime.recording.annotations` 提供读写与校验，`uv run recording check` 也校验它。帧一律以帧索引里的帧号引用，范围含两端。

| 字段 | 每项 | 规则 |
| --- | --- | --- |
| `format` | — | 1 |
| `screens` | `screen`、`first`、`last` | 按帧范围标的画面，`screen` 是适配包 `screens` 的 `id`；按 `first` 排序，互不重叠，没标的帧不属于任何画面 |
| `lines` | `speaker`、`text`、`first`、`complete`、`last` | 每一句的真值：说话人（旁白为 null）、全文、出现的帧范围；`complete` 是全文都显示出来的第一帧，没显示完就被推进时为 null；按 `first` 排序 |
| `voice` | `start_ns`、`end_ns` | 配音段，按采集时刻；按 `start_ns` 排序，互不重叠，落在录下的音频之内 |

帧号须在帧索引里，`first ≤ complete ≤ last`；文字非空，首尾不是空白。G2 的回放基准要的目标与正确的点击目标随 G2 加入，格式变化时 `format` 加一。

### 留存

- 一款游戏的用量是 `recordings/<适配包 id>/` 下各录制目录（名字合上面的格式）里全部文件的字节数，上限为 `recording_quota_gb` × 10⁹ 字节。
- 开始录制前与录制期间每 5 秒核对一次：超出上限时按目录名从旧到新删除这款游戏的其它录制（含不完整的），每删一段之前在终端打印它的目录、状态与体积；正在录的不删。只剩正在录的一段仍超出时停止录制，`stop_reason` 为 `quota`。
- 名字不合格式的目录既不计入，也不删除。导出的图与声音不在录制目录里，用完即删（C-1）。
- `uv run recording list [<适配包 id>]` 列出各段录制的状态、时长、帧数与体积，以及用量与上限。

### 导出

导出到 `<本地数据目录>/exports/<适配包 id>/<录制目录名>/`，供标定时查看（C-5）与评测工具使用。`<录制>` 可以写录制目录的路径、`<适配包 id>/<录制目录名>`，或只写 `<适配包 id>`（最新的一段完整录制）。

- `uv run recording export-frames <录制>`：以 `--frames <帧号,…>`、`--every <秒>`（按采集时刻每隔几秒取一帧）、`--stable`（每段稳定下来的第一帧，按[变化与稳定](perception.md#变化与稳定)的缺省参数）或 `--all` 选帧，`--start`、`--end`（距第一帧的秒数）限定范围。写成 `frames/<帧号>.png`（RGBA，像素与录制逐一相同），另写 `frames.jsonl`，列出导出的帧号、采集时刻与距第一帧的秒数。
- `uv run recording export-audio <录制>`：`--start`、`--end` 限定范围，写成 `audio-<起>-<止>ms.wav`，缺省 32 位浮点（WAVE 格式码 3），`--pcm16` 写 16 位整数。块号有空缺或带不连续标志、且采集时刻晚于上一块的结束时，按时差补零，所以 WAV 的第 i 个采样点就在第一块的采集时刻加 i/采样率；旁注 `.json` 写明第一块的采集时刻、采样率与补零的位置。
- `uv run recording check <录制>`：逐帧解码并校验 CRC，核对音频索引与样本文件，校验标注。

### M0 回放

（[M0 仿真](game-bridge.md#监督模式)）`uv run replay <录制>` 把一段完整的录制喂给与录制时相同的一组插件，输出能与实时运行逐条比对。`--data-dir` 给出模型制品与锚点模板所在的本地数据目录。

- **帧**：回放帧源 `ReplayFrameSource` 按帧索引的顺序逐帧解码给出，帧号、采集时刻、变换版本与像素都与实时运行时读者拿到的相同（行跨度为宽 × 4），读完即结束；解码时校验 `crc32`，不符即报错。
- **声音**：回放音频源 `ReplayAudio` 满足 `RecordedAudio`：`next_blocks` 按块号给出录下的块（每次至多 100 块），读完即结束；`voice_marks` 给出 `live/voice-feed.jsonl` 里的喂入标记，`voice-activity@1` 据此按录制喂入（[确定性与回放](perception.md#确定性与回放)）。`read_recent` 没有“现在”，回放中不支持。
- 两者都不读墙钟，读者要多快就给多快；插件全部激活之后才开始给（`start`），先激活的读者不会在订阅结果的插件激活之前就把帧读走。
- **插件**（`perception_entries`，录制时相同）：`game-adapter@1`、`ocr@1`、`scene@1`、`voice-activity@1`、`narrative@1` 与把结果写成文件的 `results`。适配包的对白框没有声明或尚未标定时不运行 `narrative@1`，记一条告警。模型制品与锚点模板取自本地数据目录；剧情记录的 SQLite 写进输出目录，与实时运行的剧情记录分开（[存储](narrative-planner.md#存储)）。没有实时核：内核的 `CoreControl` 拒绝一切提交。
- **跟上**：回放给帧比实时快。剧情记录积压超过 32 个更新时，回放帧源先等它处理完再给下一帧（`ResultsHub.pace`），不让它积压超限而丢弃，那会与实时不同。
- **结束**：每个申请了 `frames.read` 或 `audio.read` 的条目都读到结束、剧情记录处理完积压的更新（`wait_idle`）之后停内核；60 秒没有进展即报错退出。
- **输出**（`results` 插件，录制时写进 `live/`，回放时写进 `replay/`；回放每次先清空 `replay/`，`--out` 可改到别处）：

| 文件 | 每行 |
| --- | --- |
| `scene.jsonl` | 每帧一个 `SceneState` |
| `voice.jsonl` | `voice-activity@1` 的每条变化 |
| `voice-feed.jsonl` | `voice-activity@1` 的每个喂入标记，末尾是停止记录时的 `FeedEnd`；也是回放的输入 |
| `narrative.jsonl` | `narrative@1` 每句的每次变化（新建、修订、说话人、完整度、结束），即这一刻的 `NarrativeRecord`；播片段的开始与结束按处理的顺序插在其间（`type` 为 `cutscene`） |
| `narrative-final.jsonl` | 处理完全部更新后的各句（`records()`），之后是剧情范围（`type` 为 `scope`）、播片段（`cutscene`）与中断（`discontinuity`） |
| `narrative/<适配包 id>.sqlite3` | 剧情记录的存储 |

剧情记录的对象不写运行号（每次运行都新开一个），其余字段——说话人、文本、修订号、完整度、范围与各帧号——都写。枚举写取值，浮点数按 `repr` 写出、能逐位还原。

- **比对**：回放之后把 `replay/` 与 `live/` 里的上表各 `.jsonl` 逐行比对（解析成 JSON 后相等；`live/` 里没有的文件不比），打印每个文件相同的行数与第一处不同，任一不同时退出码为 1。`compare_dirs` 也可以比对任意两次运行的输出目录。适配包的 SHA-256 与录制时不同时先告警，因为签名与对白框变了结果本来就可能不同。

### 实测

合成游戏的窗口外壳 2560×1440（`--autoplay 1`，每秒推进一句，30 字/秒逐字显示），经 WGC 与 release 版实时核录 60 秒，真机手动测试 `runtime/tests/core_link/test_record_window.py`（Windows 11 Pro 10.0.26200，Intel Core Ultra 7 265K，20 个逻辑处理器，2026-11-01）。只是合成游戏上的数：它的画面是平涂的色块，关键帧很小；《魔女审判》上的数见表后。

| 项 | 只录制（`--record-only`） | 同时运行感知插件 |
| --- | --- | --- |
| 帧环帧率（外壳在这个尺寸下的重画） | 23.2 fps | 20.9 fps |
| 接纳帧率（`max_rate` 10，内容不变的帧每 0.25 秒一帧） | 5.3 fps | 5.6 fps |
| 编码：关键帧 43、差分约 200、`same` 约 80；在途的编码至多 1 帧 | 跟得上 | 跟得上 |
| 单线程编码一帧（中位数） | PNG 48 ms，差分 25 ms | 同左 |
| 每分钟体积 | 41.5 MB（帧 17.8 MB，声音 23.0 MB） | 43.2 MB（帧 18.7 MB，声音 23.3 MB） |
| 主进程 CPU（单核的百分比） | 23% | 312% |
| 实时核 CPU | 16% | 16% |
| 回放 334 帧（逐帧解码，约 16.5 fps）的耗时；与实时运行逐条比对 | 18.0 s | 17.0 s；`scene`、`voice`、`voice-feed`、`narrative`、`narrative-final` 都逐条相同 |

- 同时运行感知插件时主进程的 CPU 主要是 `narrative@1` 每次对白框变化都调用的 `ocr@1`（ONNX Runtime 算子内 4 个线程，GS-04 定），不是录制本身。
- 录声音的任务原先按 10 ms 定时，与定序帧源按 5 ms 定时一起让事件循环空转（[定序帧源](perception.md#定序帧源)），只录制时主进程约 111%；都改为 20 ms 后约 22%。
- **编码的对照**（同一台机器，单线程，2026-11-01）：两张 Windows 自带的壁纸缩放到 2560×1440，一张插画、一张照片，代替不能用于测试的游戏画面。PNG 压缩级别 1 每帧 107 与 137 ms、2.05 与 3.24 MB（级别 3 为 173 与 238 ms、1.83 与 2.94 MB；级别 6 为 440 与 634 ms、1.53 与 2.51 MB）；标准库 zlib 级别 1 直接压 BGRA 为 85 与 123 ms、2.66 与 4.16 MB；把画面 2% 的一块反色后与原图的差分（异或加 zlib 级别 1）约 20 ms、0.065 MB。合成游戏的画面 PNG 级别 1 为 47 ms、0.1 MB。PNG 编码在 1、2、4 个线程上按线程数成比例加快（插画 9.3、18.5、36.6 帧/秒）。
- 由此推算真实游戏的关键帧：按插画计每个约 2 MB，每 5 秒一个，每分钟约 24 MB；差分取决于画面上一直在动的部分，见下一条。
- **《魔女审判》**（中文版第一章开头，窗口化 2560×1440，只录制 13 分钟，同一台机器，2026-11-01）：对白画面上的粒子与闪烁的继续标记让内容几乎一直在变，接纳约 6.3 帧/秒，共 4880 帧：关键帧 251 个（变化多时写成关键帧，约每 3 秒一个）、差分 3809、`same` 820。帧 1.83 GB、声音 0.30 GB，每分钟约 141 MB 与 23 MB，50 GB 的配额约录 5 小时。M0 回放同时运行感知插件，4880 帧约 4 分钟。
- **《魔女审判》的实时只读运行**（`uv run observe witch-trial --record`，2 分 30 秒，手动推进约 20 句，同一台机器，2026-11-01）：接纳约 8 帧/秒，帧与剧情记录的积压都是 0、没有超限；主进程约 157%（单核的百分比，含 OCR 与录制的编码），实时核约 33%；每分钟约 147 MB。M0 回放 1221 帧约 1 分 51 秒，`scene`、`voice`、`voice-feed`、`narrative`、`narrative-final` 都与实时运行逐条相同。

## 标定

- 操作员在本机截图上手工标定画面签名（锚点模板、像素检查、固定文字），模板按 C-1 从本机截图裁出，存于本地数据目录并按摘要引用。
- 可用“标定”用途的模型（[模型接入](models.md#按用途配置)）生成签名候选，受 C-2 允许清单约束；候选经操作员确认后才启用。

## 经验审核

操作员查看[经验快路径](game-adapter.md#经验快路径)的候选：裁出的锚点、动作、成功次数与失败记录；批准后才启用，暂停的快路径在这里复核。

## 离线回放基准

（GR-27）

- 每款游戏以录制帧与标注做 M0 回放，输入走假后端。
- 统计：命中、错点、拒绝、按坐标执行的结果、完成每个目标的步数、调用次数与费用（来自[模型遥测](models.md#遥测)）。
- **通用度指标**：快路径关闭时通用视觉智能体的成功率（合成游戏与各游戏的录制上）、适配包中必需项之外的内容量（签名、快路径与钩子的条数）、新游戏从接入到可玩的工时；每个阶段记一次，目标是逐游戏下降。
- 接入新游戏、换模型、启用快路径候选时以此为准；结果写入不入库的报告。
- 回放中把已存样本发给云端模型须先确认 C-3，确认前只用本地模型回放。
- 测试只用合成的图。
