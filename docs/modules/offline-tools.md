# 离线工具

不进直播进程的本机工具：合成游戏夹具、录制、标定、经验审核与离线回放基准，以及并行的 VLA 研究工具。代码放在 `tools/`。产出的制品经批准才上线；从游戏派生的数据只存本地数据目录。G0 实现合成游戏，G1 实现录制与回放基准的样本格式，G2 起实现标定、回放基准与经验审核。

## 职责

- 提供不受任何游戏条款约束的合成游戏，供自动测试、真机闭环与通用度基准使用。
- 在本机录制帧、游戏声音与标注，供评测与回放。
- 帮助操作员标定快路径签名、审核经验快路径候选。
- 以回放量化每次改动的影响。

## 不负责

- **训练《魔女审判》的任何模型。** 只评测，不训练（[合规](../compliance.md)）。
- **直播路径。** 工具的结果写入不入库的报告，不直接改变运行中的配置。

## 合成游戏

（GR-30）仓库内的一个小游戏，作为测试夹具，不受任何游戏条款约束。代码是 uv 工作区成员 `tools/synthetic-game/`，发行名 `synthetic-game`，导入名 `synthetic_game`。

- **核心**：无窗口的状态机 `SyntheticGame` 加 Pillow 渲染到像素缓冲；画面含对话逐字显示、选项、计时选择、菜单、商店、弹窗与坏结局。时钟可注入：同样的输入序列在同样的时钟读数下得到同样的状态与同样的帧，测试用手动时钟推进，不真睡。分辨率（缺省 1280×720，可在 320×180 到 7680×4320 之间）、文字速度（每秒显示的字数，缺省 30）与计时选择的时长（缺省 5 秒）可配置。
- **真机**：tkinter 外壳把缓冲显示成真实窗口，经 WGC 采集与 SendInput 驱动，跑完整闭环。
- **自动测试**：缓冲经假显示面喂给[假采集源](realtime-core.md#假采集源)，假输入后端的动作回送状态机，跑除采集与注入外的全链路；Windows 真机与 Linux 容器都运行。
- **适配包**：`games/synthetic-game/`（[格式](game-adapter.md#格式)），是声明格式的第一个样例。窗口识别按下文的[窗口外壳](#窗口外壳)，期望分辨率取缺省的 1280×720；ROI 是整个客户区，以及 `layout.py` 中对话背景的钟楼、名字栏、对白文字、继续标记、选项提问、选项按钮（三个按钮的外接矩形）、计时条、菜单的三个按钮、商店列表与“离开”、弹窗与坏结局的文字和按钮的矩形除以 1280×720；画面类型映射即下表第二列；语言核对用标题菜单三个按钮的文字。快路径可整体关闭，用作通用视觉智能体的回归基准。
- **画面签名**：每个画面一个，以底色与固定面板上的像素检查为主（颜色取自 `render.py`）。对话的底色随剧情节点变，改看钟楼的钟面，另以钟面作锚点；计时选择比选项多一处计时条上的点（已走与未走的颜色都在容差内），叠加优先级更高；标题菜单与坏结局各另有一项固定文字（“开始”“重来”），没有 OCR 时这两种画面不可判。弹窗不是画面，弹窗压暗整个画面，显示时不命中任何签名。锚点模板不进版本库：`synthetic_game.anchors` 从缺省分辨率的渲染裁出钟面，编码成不压缩的 PNG（同样的像素在任何平台上得到同样的字节与摘要），测试写进临时的本地数据目录。
- 它只能证明链路通，不能代替真机验收（Bellis D-11）。

### 画面与转换

台词是为夹具原创的简短中文，画面上出现的全部文字与剧情图都定义在 `story.py`。

| 画面 | 通用画面类型 | 进入 | 操作与去向 |
| --- | --- | --- | --- |
| 标题菜单 | 菜单 | 启动、剧情读完、离开商店 | “开始”进入开场对话；“商店”进入商店；“说明”弹出说明 |
| 对话 | 对话 | 开始、选项、重来 | 逐字显示；推进时本句未显示完就先补全，已显示完就进入下一句；最后一句之后进入下一节点，个别节点先弹窗 |
| 选项 | 选择 | 开场对话读完、插曲读完 | 三个选项：进入地下的对话、插曲对话（读完回到本选项）、坏结局 |
| 计时选择 | 计时选择 | 地下对话之后的弹窗关闭 | 两个选项：坏结局、结尾对话；画面有倒计时条与剩余秒数，到截止时刻进入超时的坏结局 |
| 商店 | 商店 | 菜单 | 8 件物品，每屏 4 行，可滚动；点击一行即购买，已拥有的不变，金币不足时弹窗；“离开”回到菜单 |
| 坏结局 | 坏结局 | 选错、超时 | “重来”回到开场对话的第一句 |
| 弹窗 | 无，见下 | 菜单的“说明”、商店金币不足、地下对话读完 | 模态，只有“确定”可点；关闭后回到底下的画面，或进入预定的下一节点 |

- 结尾对话读完加 30 金币后回到菜单。金币初始 50，金币与已购物品跨画面保留，其余状态进入节点时重置。
- **逐字显示**：已显示的字数为（当前时刻 − 本句开始时刻）× 文字速度，向下取整。
- **计时**：计时选择从进入时开始计时，弹窗显示期间不计时。到截止时刻（含）即超时，转换按截止时刻本身发生，与何时被观察无关；截止之后才到达的输入落在坏结局上，不会选中选项。
- **与通用画面类型的映射**：上表第二列，取自[画面状态](perception.md#画面状态)的通用分类，真值里的画面类型直接用分类的名称。通用分类里没有弹窗，弹窗表示为叠加层：真值的画面类型仍是底下那个画面的，另以叠加层给出弹窗文字。合成游戏不产生其余通用类型（设置、存读档、加载、过场、即时玩法、地图、背包、卡住、未知）。

### 输入与真值

输入用本包自己的小类型（`synthetic_game.inputs`），对应[统一动作空间](../architecture.md#控制的组织)里会到实时核的部分，不依赖核协议；假输入后端与窗口外壳各自把动作转换成它们。坐标一律是客户区的物理像素，原点在客户区左上角。

| 输入 | 字段 | 规则 |
| --- | --- | --- |
| 点击 `Click` | 坐标，鼠标键（左、右、中） | 只有左键触发目标；目标矩形含左边与上边、不含右边与下边；有弹窗时弹窗之外的点击都算未命中 |
| 短按 `Press` | 键：回车、空格、Esc、上、下 | 上下移动光标（菜单与选项循环；商店不循环，列表随光标滚动）；回车与空格触发光标所在的目标；Esc 关闭弹窗、离开商店 |
| 滚动 `Scroll` | 坐标，格数（正数向上，与 Windows 滚轮的符号一致） | 只在商店列表内有效，一格一行，光标留在可见范围内 |

`handle` 返回这个输入的效果：命中（点中并触发了某个目标）、未命中、按键（被当前画面处理）、滚动、忽略（非左键点击、当前画面没有绑定的键、列表之外或有弹窗时的滚动），以及被触发或选中的目标与状态是否改变。

`truth` 是只给测试与假后端断言用的真值接口；运行时只能从像素感知画面，不能读它。它给出：通用画面类型、剧情节点、叠加的弹窗、当前可点的目标（标识、矩形与文字，有弹窗时只有弹窗上的目标）、键盘光标所在的目标、画面的主要文字及已显示的部分、计时剩余、金币、已购物品与上一个输入的效果。点击是否命中，以点击坐标、目标矩形与效果三者对照证明。

| 目标 | 标识 |
| --- | --- |
| 菜单项 | `menu.start`、`menu.shop`、`menu.help` |
| 对话框 | `dialogue.box` |
| 选项 | `choice.<序号>`，从 0 起 |
| 商店的行与离开 | `shop.item.<物品序号>`（只有可见的行）、`shop.leave` |
| 弹窗的确定 | `popup.ok` |
| 坏结局的重来 | `ending.retry` |

### 渲染

- `frame` 返回帧：像素、宽、高与帧号。像素为 BGRA8，自上而下逐行排列，行跨度为宽乘 4，alpha 恒为 255，与[帧环](core-protocol.md#帧环与音频环)一致。
- 帧号从 1 起，画面内容变化时才加一；内容没变时返回同一帧，同样的画面渲染出同样的像素。
- 设计稿按 1280×720，在横纵两个方向按分辨率分别缩放。点击判定与渲染共用同一组矩形，画出来的按钮就是能点中的区域。
- 文字固定用 Pillow 的基本排版引擎，不随系统是否装有 raqm 而变。

### 字体

- **来源**：Noto Sans SC Regular 2.004，取自官方仓库 notofonts/noto-cjk 发布 Sans2.004 的标签下的 `Sans/SubsetOTF/SC/NotoSansSC-Regular.otf` 与 `LICENSE`，与该发布的附件 `18_NotoSansSC.zip` 中的同名文件逐字节相同；URL 与 SHA-256 写死在 `font_subset.py`。
- **取字**：`story.py` 里的全部文字、ASCII 可打印字符与常用中文标点；不保留 OpenType 排版特性。
- **命名**：原字体的版权声明与许可都没有声明 Reserved Font Name，OFL 不强制修改版改名；子集仍改名为 Synthetic Game Sans SC（PostScript 名 `SyntheticGameSansSC-Regular`），不让这个子集以 Noto（Google 的商标）的名字出现。版权、商标、作者与许可等名称记录原样保留。原字体一旦声明了 Reserved Font Name，脚本即失败，须重新核对命名。
- **入库**：`src/synthetic_game/fonts/` 下的子集、OFL 全文 `OFL.txt`（与上游 `LICENSE` 逐字节相同）与来源说明 `SOURCE.toml`（URL、版本、原文件与子集的 SHA-256）。原字体不入库。
- **重新生成**：改了台词后在仓库根目录运行 `uv run python -m synthetic_game.font_subset`。脚本把原字体与许可下载到临时目录并核对 SHA-256，已有原文件时可用 `--source-dir` 指定（同样核对）；同样的原字体与台词总是得到逐字节相同的子集。检查核对子集的 cmap 恰好是所需的字，改了台词而没重新生成子集即失败。fontTools 是开发依赖，只有这个脚本与字体测试用到它。

### 窗口外壳

- **入口**：`uv run synthetic-game`，可加 `--width`、`--height`、`--text-cps`、`--choice-seconds`、`--redraw-hz`。
- **窗口识别**：标题 `Bellis Synthetic Game`；Win32 窗口类 `TkTopLevel`，由 Tk 固定、不能配置，所有 Tk 程序都相同，须与标题一起用；拥有窗口的进程是 uv 管理的 `python.exe`，`synthetic-game.exe` 只是启动它的启动器。Tk 类名为 `BellisSyntheticGame`，即 X11 的 WM_CLASS。
- **DPI 与尺寸**：Windows 上建窗之前把进程声明为按显示器感知 DPI v2，客户区就是配置分辨率的物理像素，WGC 采到的尺寸等于缓冲尺寸；窗口不能缩放。客户区里只有一个显示帧的标签，原点与客户区左上角重合。
- **事件**：鼠标左、中、右键按下即转成点击；滚轮增量累积到 120 为一格转成滚动，X11 的 4、5 号键各为一格；Return、space、Escape、Up、Down（含小键盘的回车与上下）转成短按，其它键丢弃。真实的鼠标键盘事件因此能经 SendInput 驱动它。
- **持续重画**：外壳按固定频率重画窗口，缺省 30 Hz，`--redraw-hz` 可改（大于 0、不超过 1000）；画面内容没变也重画。WGC 只在窗口内容变化时出帧，静止的画面不重画就没有新帧、帧龄一直增长；真实游戏一般也每帧都在绘制。每次重画取当前帧，把它重新贴进显示帧的标签。重画排在固定的时刻上，不随每次重画的耗时漂移，落后超过一个周期时不追赶；输入处理完、画面变了即刻更新，不等下一次重画。
- **实测**（Windows 11 真机，1280×720，停在静止的标题菜单，`capture-probe` 采 10 秒）：不重画时只出 1 帧；30 Hz 时 29.7 fps；60 Hz 时 49.8 fps，没达到 60 的原因未查。
- 没有 tk 或没有显示的环境（如 Linux 容器）里，外壳的测试跳过。

## 录制

- 录制帧、游戏声音与标注（画面类型、目标、正确的点击目标）存于本地数据目录，不进版本库，按游戏分开。
- 录制按该游戏的条款处理；《魔女审判》按 C-4（2026-11-01 允许）：只存本机，留存上限每款游戏 50 GB，超出时删最旧的录制；样本与 GS-04、GS-06、GS-07 共用。
- 游戏适配包的合规声明禁止时，示范记录器拒绝运行。

## 标定

- 操作员在本机截图上手工标定画面签名（锚点模板、像素检查、固定文字），模板按 C-1 从本机截图裁出，存于本地数据目录并按摘要引用。
- 可用“标定”用途的模型（[模型接入](models.md#按用途配置)）生成签名候选，受 C-2 允许清单约束；候选经操作员确认后才启用。

## 经验审核

操作员查看[经验快路径](game-adapter.md#经验快路径)的候选：裁出的锚点、动作、成功次数与失败记录；批准后才启用，暂停的快路径在这里复核。

## 离线回放基准

（GR-27）

- 每款游戏以录制帧与标注做 M0 回放，输入走假后端。
- 统计：命中、错点、拒绝、按坐标执行的结果、完成每个目标的步数、调用次数与费用（来自[模型遥测](models.md#遥测)）。
- **通用度指标**：快路径关闭时通用视觉智能体的成功率（合成游戏与各游戏的录制上）、适配包中必需项之外的内容量（签名、快路径与钩子的条数）、新游戏从接入到可玩的工时；每个阶段记一次，目标是逐游戏下降。
- 接入新游戏、换模型、启用快路径候选时以此为准；结果写入不入库的报告。
- 回放中把已存样本发给云端模型须先确认 C-3，确认前只用本地模型回放。
- 测试只用合成的图。
