# 实时核

Rust 写的独立进程，是游戏侧的安全核：采集画面与声音，并作为唯一的输入代理，在本地强制执行许可、白名单与释放（GD-01、GD-02）。它不是插件，不热替换，只在没有输入许可时更换。G0 实现启动、采集与假输入后端，G1 加音频，G2 接真实输入。

## 职责

- 按窗口采集游戏客户区，写入帧环；按进程采集游戏的声音，写入音频环。
- 按动作块执行输入，每次输入前在本地核对[权威规则](../architecture.md#权威)中的三个条件。
- 强制执行游戏适配包的动作白名单与静态禁区。
- 维护持键账目，任何失效时释放全部输入并核验。
- 检测真人接管与其他程序的注入，监听本地急停热键。

## 不负责

- **决策。** 动作由主进程的控制产出者决定。
- **识别画面。** 按画面类型的规则（危险画面、风险等级）只在主进程执行，见[动作风险](step-control.md#动作风险)；实时核不识别画面，这是剩余风险。
- **签发许可。** 许可来自 Bellis 的控制连接（[游戏桥](game-bridge.md#连接)）或独立运行的操作员入口。

## 启动与生命线

| 游戏是否提权 | 实时核的启动 |
| --- | --- |
| 不提权 | 主进程以 `subprocess.Popen` 拉起非提权子进程，停止顺序为 RPC → 关 stdin → 超时强制终止，Windows 上用 Job Object 管住孙进程（Bellis R-06） |
| 提权 | 维护者一次性注册的计划任务（GR-06），见下文 |

**提权时的计划任务（GR-06）。**
- 任务“以最高权限运行”：只按需启动、无触发器、交互令牌，重复启动时忽略新实例。
- 参照 Bellis R-26，以 `subprocess.Popen`（参数列表，不经 shell）调 `schtasks.exe /Create /XML` 注册；任务 XML 由代码生成，注册后以 `/Query /XML` 读回核对。注册由维护者本人执行。
- 主进程先把本次的连接信息写入 SecretStore，再以 `schtasks /Run` 触发；实时核自行读取主进程与 Bellis 的连接信息（Bellis R-23）。
- 正常停止经 RPC，`schtasks /End` 只作最后手段。
- 实时核程序与配置放在只有管理员能写的目录（由一次提权的安装步骤放入），防止主进程内的代码替换后借任务提权。这道防护只防程序与配置被替换；威胁模型同 Bellis D-12，不防同一用户下的恶意进程：它可以触发任务、写 SecretStore 并连上实时核，但没有 Bellis 经控制连接发给实时核的输入许可就发不出任何输入，独立运行的测试许可只在测试中使用。
- 可行性由 [GS-03](../plan/spikes.md) 验证。

**生命线。** 实时核以与主进程的核连接为生命线，断开超时即释放全部输入后退出。panic 即退出；每次启动先释放全部输入，再接受动作。

## 画面采集

用 Windows Graphics Capture 按窗口采集（GR-07），直接基于 `windows` crate 实现，`windows-capture` 等现成 crate 只作参考、不作依赖。

- 只采游戏适配包认定的窗口（进程名加窗口类或标题），找不到即没有帧；不采整屏。
- WGC 帧池 → staging 纹理 → 读回 → 帧环；BGRA8，裁到客户区，不采鼠标指针。需要降采样时先在 GPU 上缩小再读回。
- 采集时刻取 WGC 帧的系统相对时间（QPC）。
- 实时核声明为按显示器感知 DPI v2，坐标一律用物理像素；客户区偏移由 DWM 窗口边界与 `ClientToScreen` 计算；窗口移动、缩放或 DPI 变化时变换版本加一。
- 游戏须为窗口化或无边框全屏，不支持独占全屏。
- 提供假采集源供自动测试使用。

帧环由主进程创建，布局见[核协议](core-protocol.md#帧环与音频环)。待实测项见 [GS-01](../plan/spikes.md)。

## 音频采集

用 WASAPI 进程回环按游戏进程 ID（含子进程）只采游戏的声音（GR-08），PCM 带 QPC 时间戳写入音频环，与帧环同一时钟；音频环由主进程创建。不用端点回环与虚拟声卡。配音忙闲由主进程判断，见[感知](perception.md#配音检测)。

## 输入代理

### 注入

用 SendInput 注入（GR-09）：键盘发扫描码；点击把客户区物理像素换算为绝对坐标后移动、按下、按住、抬起，按住时长写在游戏适配包；每个注入事件的 `dwExtraInfo` 带本次会话的标记。不用窗口消息、虚拟 HID 或内核过滤驱动。

每次注入前核对：游戏窗口在前台，落点在客户区内，窗口未最小化且不在安全桌面，以及[权威规则](../architecture.md#权威)的三个条件。注入后再核对一次前台，焦点中途变化即报部分提交或结果未知，不自动重试。从不自动把游戏切回前台，失焦时上报并暂停输入。

### 白名单与静态禁区

游戏适配包写明允许的扫描码、鼠标键、点击区域、最高动作速率与最长按住时间，以及不论画面都不能点的静态禁区（GR-21）。实时核在白名单之外强制执行静态禁区，不满足即拒绝该动作并上报。

### 持键账目与释放

持键账目记录本许可按下的每个键。释放时逐一发抬起，并以 `GetAsyncKeyState` 核验。任何失效都按[失效与释放](../architecture.md#失效与释放)释放全部输入。

### 接管与急停

- 低层键鼠钩子在专用线程上运行，回调只入队。
- 没有“已注入”标志的真人动作（鼠标位移超过阈值才算）与不带本会话标记的注入都按接管处理：本地撤权、释放全部输入、上报。Bellis 切到人工模式，交还控制只能由操作员执行。
- 实时核同时监听 OBS 急停热键（Bellis R-27）的组合键，按下即释放全部输入并上报，不依赖 Bellis 转发；组合键在配置中与 OBS 的绑定保持一致。
- 反作弊拦截或标记注入的输入时按合规停止信号处理，不绕过。

待实测项见 [GS-02](../plan/spikes.md)。

## 动作块的执行

动作块的形式见[核协议](core-protocol.md#动作块)。实时核按时间戳执行，到有效截止时刻还没有新的动作块就释放；只接受当前控制产出者与当前代次的动作块。即时游戏需要的定时精度由 [GS-08](../plan/spikes.md) 实测。

## 验收

| 阶段 | 内容 |
| --- | --- |
| G0 | 作为子进程按 R-06 启动与停止，不残留孙进程；生命线；采集进入帧环；假输入后端上验证[失效与释放](../architecture.md#失效与释放)的每种情形 |
| G1 | 音频环只含游戏的声音 |
| G2 | 真实输入、持键账目核验、钩子与接管、急停热键、静态禁区；急停、许可过期与真人接管后释放的时延实测；《魔女审判》需要提权时（GS-05），计划任务启动与提权下的生命线 |
| 原神阶段 | 连续模式的动作块定时调度（GS-08）；此前未做时，计划任务启动与提权下的生命线 |
