# 核协议与本机通道

主进程与实时核之间的消息、动作块和共享内存的布局，以及本仓库全部本机通道的实现。G0 实现。连接的划分与各自承载的内容见[总体架构](../architecture.md#进程与连接)；与 Bellis 之间的游戏桥消息见[游戏桥](game-bridge.md#契约)。

## 本机通道

本仓库按 Bellis R-05 的规范自写 `bellis-channel/1`（GR-28），不依赖 Bellis 的 `bellis_sidecar` 包：

| 实现 | 用于 |
| --- | --- |
| Python 客户端 | 主进程 → Bellis 宿主（语义连接） |
| Python 服务端 | 主进程 ← 实时核（核连接） |
| Rust 客户端 | 实时核 → Bellis 宿主（控制连接）、实时核 → 主进程（核连接） |

- Windows 上用命名管道，其它平台用 UDS，同一抽象（Bellis D-12）。
- 双向 HMAC 认证先于任何数据；有帧长上限与超时；篡改、重放、超长帧与超时都拒绝。
- 正确性分三层：握手与帧格式的已知答案测试；本仓库 Python 与 Rust 的互通测试，Windows CI 实际跑命名管道；G3 联调前与 Bellis 宿主真机互通。

## 核协议

核连接上的消息（GR-03）：

- 以 Rust 类型为源（serde，拒绝未知字段），schemars 生成 JSON Schema 2020-12，再由 datamodel-code-generator 生成 Pydantic 模型。
- 生成物放在 `protocol/`，与源一起提交；`uv run check` 核对生成物未过期。
- 消息走 `bellis-channel/1` 帧，内容为 JSON-RPC 2.0（同 Bellis D-21）。
- 联合类型统一用带 `type` 字段的内部标签；两个生成器的配合在首个实现时验证。
- 握手校验协议版本；两端同仓库同发布，仍然校验。

核连接承载：动作块、控制产出者心跳与代次、执行回执、输入已释放的确认、实时核健康。

## 动作块

主进程向实时核提交的唯一动作形式（GD-01）。

| 字段 | 含义 |
| --- | --- |
| 产出者身份与代次 | 实时核拒绝其它产出者和旧代次的动作块 |
| 基准帧号 | 产出者做决定时依据的帧 |
| 起始时刻 | 与帧环同一时钟 |
| 动作 | 按时间戳排列，取自[统一动作空间](../architecture.md#控制的组织) |
| 有效截止时刻 | 到时还没有新的动作块，实时核即释放 |

- **持续状态**（按住的键、轴）每块完整给出，缺项按释放处理，不沿用旧值。
- **一次性动作**（点击、短按、相对位移）按身份去重，重传不重复执行、不延长持续时间。
- 剧情游戏的动作块只含一次点击或短按，没有持续状态；即时游戏的动作块是按固定频率排列的完整控制序列。

## 帧环与音频环

两者都是主进程创建的共享内存环形缓冲，实时核连接并写入（非提权一方创建全部进程间对象，GD-02）。

| 环 | 每项内容 |
| --- | --- |
| 帧环 | 帧（BGRA8，客户区）、帧号、采集时刻（QPC）、窗口与 DPI 变换版本 |
| 音频环 | 游戏进程的 PCM 与采集时刻，与帧环同一时钟 |

头部是二进制布局，以 Rust 的 `#[repr(C)]` 结构为源，由测试导出字段偏移表，Python 侧以测试核对；偏移表不一致时 `uv run check` 失败。
