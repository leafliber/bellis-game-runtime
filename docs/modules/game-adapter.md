# 游戏适配包

针对一款游戏的适配，属于主进程关键平面，提供 `game-adapter@1`（GD-04）。通用视觉智能体是底座，适配包只须提供必需项就能以逐步模式运行；快路径按需添加，用来降低时延与费用、提高可靠性。适配成本降低了，但零样本通关仍不是目标（Bellis D-02）。各游戏的具体适配见 [docs/games/](../games/)。G1 实现声明格式、合成游戏的适配包与《魔女审判》适配包的必需部分，G2 加快路径。

## 职责

- 认定游戏窗口，声明动作白名单、静态禁区与风险等级。
- 声明合规约束与允许的模型，由运行时执行。
- 提供快路径：画面签名与对应的确定性处理。
- 提供 planner 的笔记栏目、模式仲裁规则与操作员前置条件。

## 不负责

- **执行与把关。** 白名单与静态禁区由[实时核](realtime-core.md#白名单与静态禁区)执行，风险规则由[逐步控制](step-control.md#动作风险)执行。
- **存放从游戏派生的东西。** 模板、截图与录制只存本地数据目录，见下文。

## 格式

（GR-31）适配包以声明为主，逻辑为辅：

- **声明**：一个 TOML 文件写上表的全部内容；Pydantic 模型是 Schema 源，用标准库 `tomllib` 读取；`uv run check` 校验每个适配包。
- **钩子**：只有需要逻辑的快路径处理写 Python 钩子，钩子只能引用声明里的签名与 ROI，不自带坐标；钩子数量计入[通用度指标](offline-tools.md#离线回放基准)。
- 标定与经验审核的产物直接写成声明，不经人工翻译成代码。

### 声明文件

每个适配包的声明是 `games/<id>/adapter.toml`，UTF-8，换行为 LF。Schema 源是 `runtime/src/game_runtime/adapter/` 的 Pydantic 模型 `Adapter`，任何一层出现未知字段都不合法。

- **标识**：适配包、ROI、画面、签名、笔记栏目与前置条件的标识以小写字母开头，由小写字母、数字与 `-` 组成，至多 48 字符。
- **坐标**：客户区归一化坐标，原点在客户区左上角，x 向右、y 向下，取值 [0, 1]，与分辨率无关。矩形写作 `[左, 上, 右, 下]`，左 < 右、上 < 下；换算到物理像素时左右乘以客户区的宽、上下乘以高，各取最近的整数（恰为 .5 时取偶数），得到含左边与上边、不含右边与下边的矩形。点写作 `[x, y]`，落在第 ⌊x·宽⌋ 列、第 ⌊y·高⌋ 行，超出时取最后一列或最后一行。
- 坐标只写在 `rois` 与签名的像素检查里，其它地方按名字引用 ROI。
- **单位**：时间以秒计，分辨率以物理像素计。
- **输入**：扫描码为 Set 1，扩展键在高字节带 `0xE0`，TOML 里可写十六进制（如 `0xE048`）；鼠标键为 `left`、`right`、`middle`。两者同[动作块](core-protocol.md#动作块)。
- **类型**：布尔、整数与字符串之间不转换；小数字段可以写整数。

| 表 | 必需 | 字段 |
| --- | --- | --- |
| 顶层 | 是 | `id`；`name`：显示名；`version`：适配包版本，1–32 字符 |
| `window` | 是 | `process_name`，加 `window_class` 与 `title` 至少一个：规则同[窗口识别](realtime-core.md#窗口识别)，转换为采集配置的 `WindowRule` |
| `resolution` | 是 | `width`、`height`：期望的客户区分辨率，1–16384 |
| `language` | 是 | `tag`：语言版本，取 BCP 47 的语言加可选的文字与地区（如 `zh-Hans`）；`fixed_texts`：语言核对用的固定文字，可为空，见[语言核对](#语言核对) |
| `compliance` | 是 | 见[合规声明的字段](#合规声明的字段) |
| `whitelist` | 是 | 见[动作白名单](#动作白名单) |
| `screens` | 是，可为空 | 本游戏的画面：`id`、`title`、`type`，见[画面类型映射](#画面类型映射) |
| `screen_types` | 否 | 本游戏扩展的画面类型：`name`、`base`，见[画面类型映射](#画面类型映射) |
| `risk` | 是，可为空 | `forbidden_words`：本游戏的禁用词，与通用词表一起生效；`forbidden_zones`：静态禁区，ROI 名的列表；`preconditions`：操作员前置条件，每项 `id`、`text`。三项缺省为空 |
| `rois` | 否 | ROI 名 → `title`（必需）与 `rect`（归一化矩形）；没有 `rect` 即尚未标定 |
| `pacing` | 否 | 见[阅读节奏](#阅读节奏)；没有即尚未设定 |
| `signatures` | 否 | 见[画面签名](#画面签名) |
| `notes` | 否 | 笔记栏目：`id`、`title`，可选 `description`；只是结构，不含从游戏派生的内容 |

### 画面类型映射

- `screens` 的 `type` 只能是[通用画面类型](perception.md#画面状态)的名称或 `screen_types` 中声明的扩展，不能是卡住或未知。
- 扩展的 `name` 不能与通用画面类型重名；`base` 是它所属的通用画面类型，同样不能是卡住或未知。风险等级与仲裁规则的缺省按 `base` 取用（G2）。

### 语言核对

`fixed_texts` 的每项为 `screen`（出现这段文字的画面）、`roi` 与 `text`。核对在该画面的稳定帧上对 ROI 做 OCR，各行依次连接、去掉空白后包含同样去掉空白的 `text` 即该项相符（`RoiText.matches`）；当前画面声明的各项都相符才算语言相符，任一项不符即不符。列表为空即尚未标定，核对不能通过。执行见[语言核对的执行](perception.md#语言核对的执行)。

### 合规声明的字段

| 字段 | 含义 |
| --- | --- |
| `basis` | 依据：合规文档的章节与确认编号 |
| `text_source` | 只能是 `screen`：文本只从屏幕 OCR 与 VLM 获取，不解析游戏数据 |
| `training` | 是否允许把游戏画面、声音与文本用于训练或微调；为假时训练工具拒绝运行 |
| `demonstrations` | 是否允许记录真人示范；为假时示范记录器拒绝运行 |
| `recording_quota_gb` | 本机录制的留存上限，整数，单位 GB（10⁹ 字节）；0 表示不允许录制 |
| `models` | 允许接收游戏画面与文本的模型，每项 `vendor`、`model`，可为空；每一项都须在 C-2 的允许清单内，形式与核对见[允许清单](models.md#允许清单) |

### 动作白名单

除 `max_hold` 外每个字段都要写；列表可为空，不能重复。

| 字段 | 含义 |
| --- | --- |
| `click_buttons` | 可点击的鼠标键 |
| `press_keys` | 可短按的扫描码 |
| `scroll` | 是否允许滚动 |
| `click_regions` | ROI 名的列表，点击与滚动的落点须在其中之一内；允许点击或滚动时不能为空 |
| `press_duration` | 点击与短按的按住时长，大于 0、至多 0.5 秒 |
| `max_rate` | 最高动作速率：每秒至多几个一次性动作，大于 0 |
| `hold_keys`、`hold_buttons` | 可按住的扫描码与鼠标键；都为空即不允许长按 |
| `max_hold` | 最长按住时间，大于 0；有可按住的键或鼠标键时必需，没有时不能写 |

白名单与静态禁区由实时核执行（[白名单与静态禁区](realtime-core.md#白名单与静态禁区)，G2）；G1 不发输入。

### 阅读节奏

| 字段 | 含义 |
| --- | --- |
| `min_action_interval` | 动作之间的最短间隔 |
| `read_base`、`read_per_char` | 最短阅读时间为 `read_base` 加 `read_per_char` 乘以这一句的字数（不计空白） |
| `reread_base`、`reread_per_char` | 重读时的最短阅读时间，同样计算；缺省与上一行相同，不能比上一行长 |
| `voice_unknown_wait` | 配音未知时代替“配音为闲”的最长等待，从文字完整时算起，大于 0 |

用法见[配音检测](perception.md#配音检测)与[坏结局与重来](narrative-planner.md#坏结局与重来)的重读。

### 画面签名

每个签名有 `id`、`screen`（命中即判为这个画面）与 `priority`（叠加优先级，缺省 0，大的优先），以及下列组成项，全部通过即命中：

| 组成项 | 字段 | 通过的条件 |
| --- | --- | --- |
| `anchors` | `roi`、`template_sha256`、`min_score` | 锚点模板在该 ROI 内的匹配得分不低于 `min_score`（大于 0、至多 1） |
| `pixels` | `at`（点）、`color`（`#RRGGBB`）、`tolerance`（0–255） | 该点各通道与 `color` 之差都不超过 `tolerance` |
| `texts` | `roi`、`text` | 同[语言核对](#语言核对)的一项 |

- 锚点模板不进版本库：`template_sha256` 是模板文件的 SHA-256（小写十六进制），文件在本地数据目录里，见[模板文件](#模板文件)。
- 没有任何组成项的签名即尚未标定，不参与判别。
- 匹配得分的算法、按实际尺寸的缩放、不可判与叠加优先级见[画面签名的判别](perception.md#画面签名的判别)。

### 模板文件

- **格式**：PNG，8 位灰度、RGB 或 RGBA，alpha 不参与匹配；按期望的客户区分辨率从帧上裁出，不缩放。
- **位置**：本地数据目录（[术语](../architecture.md#术语)）下的 `templates/<适配包 id>/<SHA-256>.png`，文件名是文件内容的 SHA-256（小写十六进制），就是声明里的 `template_sha256`。按游戏分开，便于按游戏清理。
- **读取**：`scene@1` 激活时读入并核对：文件不在、内容的 SHA-256 与文件名不符、不是 PNG 或解不开、全部像素相同（归一化相关没有意义）时，引用它的锚点不可判，不找替代的文件。激活后不再读文件，换了模板须停用再启用 `scene`。
- **写入**：标定工具与测试按内容算出摘要再命名，先写同目录的临时文件再改名；同名文件已在且内容相符时不再写。代码在 `game_runtime.scene.templates`。
- 模板从游戏派生，只在本机，不进版本库（[位置与版本库边界](#位置与版本库边界)）；测试只用从合成游戏渲染裁出的模板。

### 校验

`uv run check` 的 `game adapters` 一项校验 `games/` 下的每个子目录（单独运行为 `uv run check-adapters`，给出目录时只校验这几个）：

1. `games/` 下只有适配包目录，每个目录里只有 `adapter.toml`，以 `.` 开头的都除外：锚点模板、截图等从游戏派生的东西不能放进来。
2. 按 Schema 校验类型、取值范围与未知字段。
3. 交叉核对：适配包的 `id` 与目录名相同；同一张表里的标识不重复；引用的画面都已声明，引用的 ROI 都已声明且已标定；画面类型映射、模型与白名单符合上文的规则。
4. 尚未标定的项不算错误，逐项列出：没有 `rect` 的 ROI、没有组成项的签名、空的 `fixed_texts`、没有 `pacing`。

任一适配包不合法，这一项即失败。

### 尚未标定

使用方取用尚未标定的 ROI、阅读节奏或语言核对的固定文字时得到 `NotCalibratedError`，写明游戏与项；使用方据此停用依赖它的功能并报告，不回退到缺省值，也不猜测坐标。

### G1 不实现

以下 unsupported，声明里写了即是未知字段：

- 钩子与快路径的处理、模式仲裁规则（G2；剧情游戏的仲裁始终选逐步控制器）。
- 按画面类型的风险等级与危险画面签名（G2，GR-21、GR-32）。
- 白名单里按画面类型加入的条目（如坏结局上的重来入口）、轴与鼠标相对位移。
- 经验快路径。

声明在 G1 只被读取与校验；语言核对、白名单与风险的执行由各自的使用方实现。

## 插件与服务

关键平面插件 `game-adapter` 把操作员在 profile 里选定的适配包交给其它插件：

- **配置**：`game` 为适配包的 `id`；`games_dir` 可选，绝对路径，缺省为本仓库的 `games/`。
- **激活**：读取并校验 `<games_dir>/<game>/adapter.toml`，提供 `game-adapter@1`。服务就是校验过的 `Adapter`，只读；`window_rule()` 转为采集配置的 `WindowRule`，`roi()`、`require_pacing()` 与 `language_check()` 取用可能尚未标定的项，`uncalibrated()` 列出尚未标定的项。尚未标定的项另记告警日志。
- **失败**：配置不合法即停在 FAILED（`config-invalid`）；适配包不存在或不合法即激活失败，按内核的退避重试。依赖 `game-adapter@1` 的插件在它激活前停在 WAITING（`service-missing`）。
- 不申请权限。激活后不再读文件，改了声明须停用再启用。

## 位置与版本库边界

（GR-04）适配包放在本仓库 `games/<id>/`。

- **进版本库**：声明文件与钩子代码（[格式](#格式)），即上表的规则、白名单、ROI、参数、声明与笔记栏目定义。
- **不进版本库**：从游戏派生的东西（截图裁出的锚点模板、评测用截图与录制、经验与快路径候选）与模型制品。由本机工具生成或放入版本库外的本地数据目录，以版本与摘要引用；本机能否使用游戏截图以[合规](../compliance.md#合规确认)为准。
- **制品**：布局与模板、模型权重、提示词以版本加摘要加批准记录管理；更换制品等同改配置，持有输入许可时不生效。
- 需要不同的授权或合规边界、出现外部贡献、或发布节奏明显不同时，再拆为独立仓库，按 `game-adapter@主版本` 接回。

### 模型制品

模型文件（权重、字表等）不进版本库，钉住的来源与摘要进版本库：

- **清单**：每个制品一项 `Artifact`（`runtime/src/game_runtime/artifacts.py`），写明制品名、版本、文件名、大小、SHA-256、下载地址、来源与许可；清单由使用它的插件放在自己的代码里（[OCR](perception.md#模型制品)、[配音检测](perception.md#语音检测模型)），以 `all_artifacts()` 给出，改清单就是改代码，随 PR 审核。下载地址只用官方或模型作者的发布地址，钉在一个发布版本上；作者不发布所需格式时写明取自哪个转换者的发布及原因。
- **位置**：本地数据目录下的 `models/<制品名>/<版本>/<文件名>`（本地数据目录见[总体架构](../architecture.md#术语)）。
- **核对**：插件每次加载都核对大小与 SHA-256，不缓存核对结果；没有即 `ArtifactMissingError`，不符即 `ArtifactDigestError`，都写明制品、路径与应有的摘要，依赖它的插件激活失败。运行时只读本地文件、不联网，不自动下载。
- **获取**：`uv run fetch-models`（离线工具 `tools/fetch-models/`）汇总各插件的清单（`fetch_models.CATALOGS`；新的插件带了清单就把它的 `all_artifacts` 加进去；同名同版本的制品只留一项，写法不同即报错），把其中没有或不符的制品下载到本地数据目录：只从清单的 https 地址下载，重定向到非 https 即失败；边下载边算摘要，大小与摘要都相符才改为正式文件名，否则删除并失败。`--check` 只核对、不联网，`--only <制品名>` 只处理指定的制品，`--list` 列出清单。

## 合规声明

适配包声明该游戏的文本来源与训练用途等约束，以及允许接收游戏画面与文本的模型厂商与型号。运行时执行：

- [模型接入](models.md#允许清单)只向清单内的模型外发。
- 示范记录器与训练工具读到禁止声明即拒绝运行。

## 快路径

快路径为高频或有时限的画面提供确定性处理，命中时代替通用视觉智能体决定动作；有时限的画面与高频动作（如对白推进）须有快路径。签名的判别见[感知](perception.md#画面变化与签名)。

快路径有三个来源，都在操作员确认后才启用：

- **手写**：在适配包中编写规则，签名手工标定。
- **VLM 辅助标定**：离线工具用“标定”用途的模型生成签名候选（[离线工具](offline-tools.md#标定)）。
- **经验快路径**：见下文。

## 经验快路径

（GR-22）只记录与匹配，不训练任何模型。

- **记录**：动作执行后效果核验通过即记一条经验，含画面指纹（降采样画面哈希，遮掉变化区域；画面上的固定 OCR 文字；观察到的画面类型）、归一化后的目标、动作（动作类型与目标的 OCR 文字或界面元素，不存原始坐标，下次在当前帧上重新定位）、预期效果与核验结果。只记普通等级的推进类与导航类动作；选择类、不可逆与禁止等级不记。
- **候选**：同类画面、同类目标连续成功若干次（缺省 3 次）且动作一致，即生成快路径候选（从本机帧裁出的锚点模板加固定文字、动作规则、预期效果）。离线回放基准可用后，候选先在基准上验证。
- **示范**（原神阶段）：条款允许的游戏上，真人接管期间钩子看到的输入与对应的帧也按同样的格式记为经验，生成的候选走同样的审核；在《魔女审判》上记录真人示范须先登记合规确认，确认前不记。
- **审核**：操作员在本机工具中查看裁出的锚点、动作、成功次数与失败记录，批准后才启用（[离线工具](offline-tools.md#经验审核)）。
- **运行**：命中后照样核验效果，失败一次即这一步退回通用视觉智能体，该快路径暂停待复核；游戏或适配包版本变化时相关快路径全部暂停；签名命中率下降时告警。
- **存储**：经验与候选存于本地数据目录，按游戏、适配包版本与分辨率分开，不进版本库。操作员可手动把不从游戏派生的规则部分并入适配包配置，锚点模板始终不进版本库。只保留生成签名所需的裁剪区域，完整帧在候选生成或审核后删除，留存有上限（C-1）。
- **外发**：经验不作为示例图发给云端模型，只可给智能体简短的文字提示。
