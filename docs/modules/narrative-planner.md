# 剧情记录与规划

主进程中理解剧情、为 Bellis 与通用视觉智能体提供依据的两个普通插件：`narrative@1` 记录剧情，`planner@1` 理解与规划（GR-14）。它们属于游戏控制分层中的规划与理解层；Bellis 决策模型只做选择与表达。G1 实现剧情记录，G2 实现 planner。

## 职责

- 逐句记录屏幕上的剧情与画面观察，判断完整度。
- 维护滚动的剧情摘要与游戏笔记。
- 给 Bellis 局面摘要、看点标记与决策点的候选。
- 给通用视觉智能体当前目标及其完成条件。
- 处理坏结局后的失败记录与重来节奏。

## 不负责

- **选择。** planner 不做选择：无计时的选项由 Bellis 决定开投票或自选；有计时的选项到余量线 Bellis 仍未回复，即执行排第一的候选（Bellis D-07），执行见[决策点](step-control.md#决策点)。
- **外部攻略。** 只看本次游玩、当前剧情范围内的内容，不注入攻略；Game Runtime 不设注入攻略或提示的通道，操作员给的方向经 Bellis 的 `goal.submit` 传来。
- **解说节奏。** 是否解说、何时开口由 Bellis 决定，见[看点与暂缓推进](game-bridge.md#看点与暂缓推进)。

## 剧情记录

`narrative@1`，权限 `narrative.write`：

- **数据来源**：对白快路径的 OCR（名字栏与对白框）；通用视觉智能体的画面观察（[逐步控制](step-control.md#通用视觉智能体)），与对白在同一条时间线上、带帧号引用。
- **一句的边界**：逐字显示期间只更新同一句的修订号；连续若干帧不变或出现“继续”图标才算完整；对白框清空或换了内容才算新的一句，不只按文本哈希去重；未读完整即被推进的记为缺口。
- **每条记录**：出现编号、说话人、文本、修订号、首次与最后出现的时刻、完整度（部分、完整、缺口）、帧号引用、剧情范围；OCR 置信度低的行标出。
- **存储**：本机 SQLite，不进版本库，留存有上限。
- **不出本机**：完整日志不给 Bellis，也不写入 Iris（[合规](../compliance.md)）；交给 Bellis 的只有当前这一句、局面摘要与带短引用的候选。
- 记录剧情不调用模型。

## 规划

`planner@1`，模型经[模型接入](models.md)调用（推理、摘要、关键帧三个用途分别配置），外发受 C-2 允许清单约束。游戏文本在提示词中以引用的数据出现，不当作指令；输出按结构化格式校验（同 Bellis R-17 用 `json_object`）。

planner 产出三样东西：

| 产出 | 内容 | 去向 |
| --- | --- | --- |
| 局面摘要 | 画面类型（[通用分类](perception.md#画面状态)）、简短摘要、当前这一句（直接取自剧情记录）、可交互的东西、看点标记；不含整段日志 | Bellis（`situation.observed`） |
| 决策候选 | 排好序，附理由与所引的剧情记录，引用只截短句；审判发言出现时即增量计算，计时选项打开时候选已备好 | Bellis（`decision_point.opened`） |
| 当前目标 | 由 Bellis 的 `goal.submit` 与当前剧情状态拆出，附完成条件与超时，可一次给出有先后的几个子目标 | 通用视觉智能体 |

**完成条件**（GR-23）尽量能用确定性方式检查：某个画面签名命中、某个区域出现或消失某段文字、快路径给出的画面类型变为某一类；找不到时标为“由智能体判断”。超时按步数或秒数，到时由逐步控制器报 planner 重新规划，并计入卡住。满足一个子目标的条件即自动进入下一个，不再调用 planner。planner 不看截图逐步规划，看截图只在[关键帧](#游戏笔记)上。

## 调用时机

（GR-17）

- **批量更新**：滚动摘要与笔记在有未处理的句子时至多每隔一段时间（缺省 45 秒，可配置）更新一次；场景切换与 CG、获得证据等画面事件立即更新。每次调用只发当前摘要、笔记与新增的句子，不发整段日志；摘要过长时定期压缩。
- **立即调用**：审判发言（逐句增量计算候选）、决策点打开、坏结局与收到新目标；调用前先补齐未处理的句子。
- **单个在途调用**：新的触发合并进去；决策点与审判发言可取消在途的摘要更新；每次调用有超时。

局面摘要中的摘要与看点标记至多滞后一个间隔，不影响候选。

## 游戏笔记

（GR-25）

- 笔记栏目由游戏适配包定义，planner 本身不随游戏改写：剧情推理类为角色、证据、证词、疑点与矛盾，RPG 类为任务、地图、背包、队伍等。栏目定义只是结构，不含从游戏派生的内容，可以进版本库。
- 智能体的画面观察在批量更新时写入笔记。
- planner 可在关键帧（场景切换、决策点打开）上调用多模态模型（“关键帧”用途），受 C-2 允许清单约束，图像按该用途的图像规格裁剪缩小；同样遵守单个在途调用规则。关键帧调用是为了把没有文字的局面写进笔记与摘要，不是为描述画面而单独调用 VLM（GR-19）：智能体对同一帧的观察已可用时先交给 planner，只在观察不足以更新笔记时才发关键帧调用，避免同一帧外发两次。

## 看点标记

（GR-20）planner 在批量更新中给出新证据、新证词、矛盾或疑点与反转；章节与审判的开始与结束、坏结局与卡住由快路径或下文直接给出。标记的格式与用途见[游戏桥](game-bridge.md#看点与暂缓推进)。

## 坏结局与重来

（GR-15）不使用攻略，只凭本局读到的剧情推理。

- **识别**：游戏适配包的“失败与重来”快路径以画面签名识别坏结局或游戏结束画面；没有快路径时由智能体按画面、planner 按文字判断。识别后上报画面类型“坏结局”与一句摘要：哪个决策点、选了什么、来源是自选、投票还是超时默认。
- **节奏**：进入坏结局即停止推进，planner 把当前目标设为“等待”；Bellis 解说完提交继续的目标后才重来。Bellis 一直不回复时保持不动，不设自动继续。
- **重来**：只用游戏自带的重来入口，由游戏适配包按画面类型开放；不在决策点前主动存档。各游戏的重来方式写在其适配文档。
- **跨剧情范围保留**：重来点之前的剧情记录与摘要；失败记录（决策点按选项文字与前文匹配，记所选项与结果摘要）；坏结局中得知的信息，只存摘要。失败分支的剧情记录另标为一个剧情范围，滚动摘要回到重来点。读档或重来都生成新的剧情范围。
- **已试过**：同一决策点再次出现时，失败过的选项在候选中标为“已试过，导致坏结局”，排到最后并附结果摘要；是否重开投票或排除该项由 Bellis 决定。
- **重读**：重读已读过的对白时，局面摘要标为“重读”；游戏适配包可为重读设较短的阅读时间，仍不快进。
- **卡住**：同一决策点连续失败达到上限（缺省 3 次，可配置），或目标超时、同一画面多次被拒，即不再给出继续的目标，上报“卡住”，由 Bellis 决定开投票、继续自选或请操作员处理。操作员可随时接管。

## 验收

| 阶段 | 内容 |
| --- | --- |
| G1 | 维护者手动游玩一段剧情时，剧情记录逐句正确，完整、部分与缺口的判定正确；同一段录制在 M0 回放中得到同样的结果 |
| G2 | 候选在计时选项打开时已备好；坏结局后等待目标再重来；失败选项标为已试过；连续失败达上限上报卡住 |
| G3 | 交给 Bellis 的只有当前这一句、摘要与短引用 |
