# 剧情记录与规划

主进程中理解剧情、为 Bellis 与通用视觉智能体提供依据的两个普通插件：`narrative@1` 记录剧情，`planner@1` 理解与规划（GR-14）。它们属于游戏控制分层中的规划与理解层；Bellis 决策模型只做选择与表达。G1 实现剧情记录，G2 实现 planner。

## 职责

- 逐句记录屏幕上的剧情与画面观察，判断完整度。
- 维护滚动的剧情摘要与游戏笔记。
- 给 Bellis 局面摘要、看点标记与决策点的候选。
- 给通用视觉智能体当前目标及其完成条件。
- 处理坏结局后的失败记录与重来节奏。

## 不负责

- **选择。** planner 不做选择：无计时的选项由 Bellis 决定开投票或自选；有计时的选项到余量线 Bellis 仍未回复，即执行排第一的候选（Bellis D-07），执行见[决策点](step-control.md#决策点)。
- **外部攻略。** 只看本次游玩、当前剧情范围内的内容，不注入攻略；Game Runtime 不设注入攻略或提示的通道，操作员给的方向经 Bellis 的 `goal.submit` 传来。
- **解说节奏。** 是否解说、何时开口由 Bellis 决定，见[看点与暂缓推进](game-bridge.md#看点与暂缓推进)。

## 剧情记录

普通插件 `narrative`（GR-14）提供 `narrative@1`，逐句记录屏幕上的对白，代码在 `runtime/src/game_runtime/narrative/`。G1 只有对白的 OCR 一个来源；通用视觉智能体的画面观察（[逐步控制](step-control.md#通用视觉智能体)）在 G2 加入，与对白在同一条时间线上、带帧号引用。

- **不出本机**：完整日志不给 Bellis，也不写入 Iris（[合规](../compliance.md)）；交给 Bellis 的只有当前这一句、局面摘要与带短引用的候选。
- 记录剧情只用本机的 OCR，不调用 VLM 或其它模型，不外发。

### 数据来源

- 依次处理 `scene@1` 的每个更新（[输出](perception.md#输出)的 `subscribe`），按处理的顺序，不跳过。
- 只在适配包声明了[对白框](game-adapter.md#对白框)的画面上读文字：本帧的判别结果是这个画面（`verdict` 为 `screen`）时，以 `ocr@1` 识别名字栏与对白文字两个 ROI（[OCR](perception.md#接口)），归一化矩形按本帧的宽高换算；其它帧不做 OCR。
- 同一 ROI 的像素与识别过的相同时沿用那次的结果，不再识别（按 ROI 与像素内容的摘要缓存最近 32 项），所以只在逐字显示与换句时识别。
- **继续标记**：对白框声明的 `continue_signature` 在本帧的签名结果（`SceneState.signatures`）为命中即标记可见；不命中或不可判即不可见。
- **比较文本**：一个 ROI 读出的各行依次连接，做 NFKC 归一（全角与半角标点视为相同）并去掉全部空白，用于下文的比较。记录里存的是各行依次连接的原文（`OcrResult.text`）。

### 一句的边界

每处理一个更新，按本帧的情形：

| 本帧 | 处理 |
| --- | --- |
| 对白框画面，对白文字的比较文本为空 | 对白框清空：结束当前句 |
| 对白框画面，与当前句是同一句 | 更新当前句：比较文本变了即修订号加一，记录的文字换成这次读到的 |
| 对白框画面，与当前句不是同一句，或没有当前句 | 结束当前句，新开一句 |
| 判出了画面，但不是对白框画面 | 结束当前句 |
| 没有判出画面（不命中、歧义、不可判、停用），或这一帧的 OCR 出错 | 不改变任何记录，也不计入下文的连续帧数：弹窗、过场与淡入淡出时对白可能还在 |

**同一句**须同时满足：

- 同一个对白框画面。
- 名字：本帧与当前句读到的名字都不为空且不同即不是同一句；有一边为空（名字栏淡入、旁白）不算不同。记录的说话人取这一句第一次读到的非空名字。
- 文字：当前句的比较文本为 a（n 个字），本帧为 b；b 的前 n 个字与 a 的编辑距离不超过 ⌊n/4⌋。逐字显示时 b 以 a 开头；容差留给 OCR 在逐字显示中途读错个别字。b 比 a 短得多就是重新开始的逐字显示，是新的一句。

不按文本哈希去重：对白框清空、换了画面或换了内容之后再出现的同样文字是新的一句；一直没有清空、也没换内容的同一段文字始终是同一句。

### 完整度

| 完整度 | 条件 |
| --- | --- |
| 部分 `partial` | 还在显示，尚未判为完整 |
| 完整 `complete` | 比较文本连续 `complete_frames`（缺省 3）个对白框帧不变，且从它最近一次变化起已过 `complete_after`（缺省 0.5 秒，按采集时刻）；或本帧继续标记可见 |
| 缺口 `gap` | 一句在部分时被结束：未读完整即被推进、换了画面，或积压超限丢了更新（见下文）；记录里的文字只是它的一部分 |

- 完整之后比较文本又变了即回到部分：逐字显示中途的停顿被判为完整时自行纠正。
- 完整的句子被结束时仍是完整。插件停用时还没结束的句子保持当时的完整度，不记为缺口。
- 参数按游戏调整在标定时进行（GS-04 记录逐字显示的完整判定）。

### 剧情范围

范围号在一次运行内从 1 起。判出类型为坏结局或存读档（含以它们为 `base` 的扩展）的画面后，下一句开始新的范围，记下触发它的画面：重来与读档都生成新的剧情范围（[坏结局与重来](#坏结局与重来)）。失败分支的另行标注由 G2 的 planner 做。

### 记录

| 字段 | 含义 |
| --- | --- |
| `session` | 运行号：插件每激活一次新开一个，在存储里递增 |
| `occurrence` | 出现编号：本次运行内按出现的顺序从 1 起 |
| `scope` | 剧情范围号 |
| `screen` | 对白框所在的画面 |
| `speaker` | 说话人；没有名字栏或一直读不到名字时为空 |
| `text` | 文字：最近一次修订读到的原文 |
| `revision` | 修订号：从 1 起，比较文本每变一次加一 |
| `completeness` | 完整度：`partial`、`complete`、`gap` |
| `first_frame`、`first_ns` | 首次出现的帧号与采集时刻 |
| `last_frame`、`last_ns` | 最后出现的帧号与采集时刻 |
| `revision_frame` | 读出当前文字的帧号 |
| `complete_frame` | 判为完整的帧号；现在不是完整时为空 |
| `closed_frame` | 结束这一句的帧号（清空、新的一句或别的画面的那一帧）；还没结束时为空 |
| `low_confidence` | 当前修订里识别置信度低于 `low_confidence`（缺省 0.8）的行：ROI、文字与置信度。低于 OCR 的 `min_confidence` 的行在 OCR 里已丢弃 |

### 处理顺序与积压

- scene 的监听者只把更新放进队列：对白框画面的帧在这时拷出两个 ROI 的像素，不留整帧，与上一帧相同的像素共用一份。一个任务按顺序逐个处理：OCR 在 `ocr@1` 的工作线程里，写库在存储自己的线程里，不阻塞事件循环。处理慢时积压，不跳过。
- 积压上限 `max_backlog`（缺省 600 个更新，30 fps 时约 20 秒）。满了之后到来的更新丢弃，并一直丢到积压降到一半；丢掉的一段（首末帧号与个数）记为一处**中断**，排在队列里它所在的位置。处理到中断即结束当前句（部分的记为缺口），记 ERROR 日志并存入存储。有中断的运行不保证与回放的结果相同。
- 停用时取消处理任务：在途的识别由 `ocr@1` 做完后丢弃结果（[线程与时延](perception.md#线程与时延)），在途的写库做完；还没处理的更新丢弃，记告警；当前句的最新状态写库。要比对结果的回放先等积压处理完（`wait_idle`）再停用。

### 确定性

记录只取决于依次处理的 scene 更新与 OCR 结果：时刻一律取帧的采集时刻，不读墙钟，也不按处理的快慢决定任何事。除运行号外，两次处理同样的更新序列得到相同的记录；OCR 对同样的像素给出同样的结果，缓存不改变结果。实时运行与 M0 回放处理同样的帧序列由定序帧源保证（[录制](offline-tools.md#录制)）。

### 存储

- 本机 SQLite（Python 标准库 `sqlite3`，WAL），位置是本地数据目录（[术语](../architecture.md#术语)）下的 `narrative/<适配包 id>.sqlite3`，按游戏分开。删掉这个文件（连同同名的 `-wal` 与 `-shm`）即清除该游戏的全部剧情记录。不进版本库，不出本机。
- **录制与回放**：录制时实时运行的与 M0 回放的剧情记录不写进上面这个文件，`data_dir` 分别是录制目录的 `live/` 与 `replay/`，存储即那里的 `narrative/<适配包 id>.sqlite3`，随录制留存与删除；比对用的逐条输出见 [M0 回放](offline-tools.md#m0-回放)。
- 表：`sessions`（运行号、适配包版本）、`scopes`（运行号、范围号、触发的画面、首帧）、`records`（上表的字段，主键为运行号加出现编号）、`discontinuities`（运行号、首末帧号、个数）。处理一个更新产生的变化在一个事务里写入，记录按主键覆盖为新状态；只有最后出现的帧号与时刻变了的不单独写，随这一句的下一次变化或停用时写入。
- **留存**：激活时新开运行后删除最旧的运行，只留最近 `keep_sessions`（缺省 20）个；记录总数仍超过 `max_records`（缺省 200000）时继续删最旧的，当前运行不删。删除后回收空闲页。

### 服务

`narrative@1`（`NarrativeService`），G2 的 planner 与只读运行入口从这里读：

| 成员 | 含义 |
| --- | --- |
| `session` | 本次运行号 |
| `latest` | 出现编号最大的一句的最新状态，即当前这一句；还没有时为 None |
| `records(after=0)` | 本次运行中出现编号大于 `after` 的各句的最新状态，按出现编号 |
| `scopes`、`discontinuities` | 本次运行的剧情范围与中断 |
| `subscribe(listener)` | 每句每变一次（新建、修订、说话人、完整度、结束），监听者按处理的顺序收到它的新状态；只有最后出现的帧号与时刻变了不通知，`latest` 与 `records` 里总是最新的。在事件循环里同步调用，抛错只记录；返回取消订阅的函数，订阅方登记为撤销函数 |
| `processed_frame`、`backlog` | 最近处理完的更新的帧号；还没处理的更新个数 |
| `wait_idle()` | 协程，等到积压处理完 |

### 插件

- **清单**：普通插件 `narrative`，提供 `narrative@1`；依赖 `game-adapter@1`、`scene@1` 与 `ocr@1`，都是必需的：没有 OCR 就读不到文字，缺 OCR 时停在 WAITING（`service-missing`），而不是激活后什么也记不下；权限 `narrative.write`。
- **配置**：`complete_frames`（至少 1）、`complete_after`（秒，不小于 0）、`low_confidence`（[0, 1]）、`max_backlog`（至少 2）、`keep_sessions`（至少 1）、`max_records`（至少 1），以及 `data_dir`：本地数据目录，绝对路径，缺省按[术语](../architecture.md#术语)中的位置与 `BELLIS_GAME_RUNTIME_DATA`。
- **激活**：取适配包的对白框（`require_dialogue_boxes`）：没有声明即 `LookupError`，引用的 ROI 或继续标记的签名尚未标定即 `NotCalibratedError`，一次列出全部未标定的项，激活失败，不猜坐标（《魔女审判》在第 9 步标定前就是这样）；在线程里打开存储、新开运行并清理；订阅 `scene@1`，提供 `narrative@1`。
- **运行**：OCR 出错时这一帧按上表最后一行处理，记告警，恢复前不重复记录；写库出错记 ERROR 日志，内存里的记录照常更新。
- **停用**：取消订阅，取消处理任务（见上文），关闭存储。

## 规划

`planner@1`，模型经[模型接入](models.md)调用（推理、摘要、关键帧三个用途分别配置），外发受 C-2 允许清单约束。游戏文本在提示词中以引用的数据出现，不当作指令；输出按结构化格式校验（同 Bellis R-17 用 `json_object`）。

planner 产出三样东西：

| 产出 | 内容 | 去向 |
| --- | --- | --- |
| 局面摘要 | 画面类型（[通用分类](perception.md#画面状态)）、简短摘要、当前这一句（直接取自剧情记录）、可交互的东西、看点标记；不含整段日志 | Bellis（`situation.observed`） |
| 决策候选 | 排好序，附理由与所引的剧情记录，引用只截短句；审判发言出现时即增量计算，计时选项打开时候选已备好 | Bellis（`decision_point.opened`） |
| 当前目标 | 由 Bellis 的 `goal.submit` 与当前剧情状态拆出，附完成条件与超时，可一次给出有先后的几个子目标 | 通用视觉智能体 |

**完成条件**（GR-23）尽量能用确定性方式检查：某个画面签名命中、某个区域出现或消失某段文字、快路径给出的画面类型变为某一类；找不到时标为“由智能体判断”。超时按步数或秒数，到时由逐步控制器报 planner 重新规划，并计入卡住。满足一个子目标的条件即自动进入下一个，不再调用 planner。planner 不看截图逐步规划，看截图只在[关键帧](#游戏笔记)上。

## 调用时机

（GR-17）

- **批量更新**：滚动摘要与笔记在有未处理的句子时至多每隔一段时间（缺省 45 秒，可配置）更新一次；场景切换与 CG、获得证据等画面事件立即更新。每次调用只发当前摘要、笔记与新增的句子，不发整段日志；摘要过长时定期压缩。
- **立即调用**：审判发言（逐句增量计算候选）、决策点打开、坏结局与收到新目标；调用前先补齐未处理的句子。
- **单个在途调用**：新的触发合并进去；决策点与审判发言可取消在途的摘要更新；每次调用有超时。

局面摘要中的摘要与看点标记至多滞后一个间隔，不影响候选。

## 游戏笔记

（GR-25）

- 笔记栏目由游戏适配包定义，planner 本身不随游戏改写：剧情推理类为角色、证据、证词、疑点与矛盾，RPG 类为任务、地图、背包、队伍等。栏目定义只是结构，不含从游戏派生的内容，可以进版本库。
- 智能体的画面观察在批量更新时写入笔记。
- planner 可在关键帧（场景切换、决策点打开）上调用多模态模型（“关键帧”用途），受 C-2 允许清单约束，图像按该用途的图像规格裁剪缩小；同样遵守单个在途调用规则。关键帧调用是为了把没有文字的局面写进笔记与摘要，不是为描述画面而单独调用 VLM（GR-19）：智能体对同一帧的观察已可用时先交给 planner，只在观察不足以更新笔记时才发关键帧调用，避免同一帧外发两次。

## 看点标记

（GR-20）planner 在批量更新中给出新证据、新证词、矛盾或疑点与反转；章节与审判的开始与结束、坏结局与卡住由快路径或下文直接给出。标记的格式与用途见[游戏桥](game-bridge.md#看点与暂缓推进)。

## 坏结局与重来

（GR-15）不使用攻略，只凭本局读到的剧情推理。

- **识别**：游戏适配包的“失败与重来”快路径以画面签名识别坏结局或游戏结束画面；没有快路径时由智能体按画面、planner 按文字判断。识别后上报画面类型“坏结局”与一句摘要：哪个决策点、选了什么、来源是自选、投票还是超时默认。
- **节奏**：进入坏结局即停止推进，planner 把当前目标设为“等待”；Bellis 解说完提交继续的目标后才重来。Bellis 一直不回复时保持不动，不设自动继续。
- **重来**：只用游戏自带的重来入口，由游戏适配包按画面类型开放；不在决策点前主动存档。各游戏的重来方式写在其适配文档。
- **跨剧情范围保留**：重来点之前的剧情记录与摘要；失败记录（决策点按选项文字与前文匹配，记所选项与结果摘要）；坏结局中得知的信息，只存摘要。失败分支的剧情记录另标为一个剧情范围，滚动摘要回到重来点。读档或重来都生成新的剧情范围。
- **已试过**：同一决策点再次出现时，失败过的选项在候选中标为“已试过，导致坏结局”，排到最后并附结果摘要；是否重开投票或排除该项由 Bellis 决定。
- **重读**：重读已读过的对白时，局面摘要标为“重读”；游戏适配包可为重读设较短的阅读时间，仍不快进。
- **卡住**：同一决策点连续失败达到上限（缺省 3 次，可配置），或目标超时、同一画面多次被拒，即不再给出继续的目标，上报“卡住”，由 Bellis 决定开投票、继续自选或请操作员处理。操作员可随时接管。

## 验收

| 阶段 | 内容 |
| --- | --- |
| G1 | 维护者手动游玩一段剧情时，剧情记录逐句正确，完整、部分与缺口的判定正确；同一段录制在 M0 回放中得到同样的结果 |
| G2 | 候选在计时选项打开时已备好；坏结局后等待目标再重来；失败选项标为已试过；连续失败达上限上报卡住 |
| G3 | 交给 Bellis 的只有当前这一句、摘要与短引用 |
