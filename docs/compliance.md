# 合规

这是 Game Runtime 的工程准入清单，不是法律意见。法规、直播平台与 AI 标识等要求以 [Bellis 合规](https://github.com/leafliber/bellis/blob/main/docs/compliance.md)为准；本文件只写与游戏内容相关、由本仓库执行的部分。下列用法是否允许由维护者确认，确认前依赖它的路线不批准、不实现。

## 《魔法少女的魔女审判》

依据官方的[配信・二次創作ガイドライン](https://manosaba.com/guidelines)（2026-10-21 更新，2026-10-27 读取原文）。与本仓库相关的条款：

- **第 5 条**：直播标题须含「魔法少女ノ魔女裁判」。标题由推流侧处理，按 Bellis 合规执行，本仓库不涉及。
- **第 6 条**：禁止把游戏内的图像、影像、声音、剧本与文本等用作或提供为生成 AI 与机器学习模型的学习数据；以 AI 制作的作品发布时须注明“AI利用”。AI 标识的执行按 Bellis 合规处理，本仓库不涉及。
- **第 7 条**：禁止经数据解析抽取游戏内原始数据并再利用或再配布；禁止把 UI 等官方素材原样转载或再公开，实况、评论与考察所需范围内使用截图与录像不受此限；禁止以全部剧本的文字稿等可替代本篇的形式公开。

由此对本仓库的约束（游戏适配包的合规声明写明这些约束，由运行时执行，见[游戏适配包](modules/game-adapter.md#合规声明)）：

- 文本只用屏幕 OCR 与 VLM 获取，不解析游戏数据（Bellis 合规）。
- 游戏画面、声音与文本不进入任何训练或微调数据集，示范记录器与训练工具读到禁止声明即拒绝运行。
- 完整剧情日志不出本机，不给 Bellis，不写入 Iris；交给 Bellis 的只有当前这一句、局面摘要与带短引用的决策候选（见[剧情记录与规划](modules/narrative-planner.md#剧情记录)）。
- 游戏截图、录制、锚点模板、剧情记录与经验快路径只存本地数据目录，不进版本库；测试只用合成的图像与文本。

### C-2 的依据与条件

第 6 条连“提供”为学习数据也禁止，所以须先核对厂商条款是否承诺不把请求数据用于训练。2026-10-27 读取：

- 火山方舟平台专用条款（2026-08-05 版）3.7.7 与豆包模型服务协议（2026-09-18 版）4.1：未经单独同意，不把请求与输出用于训练或改进模型。单独同意包括签署《数据授权使用协议》与参加协作奖励计划；合规审查（含建立风险过滤机制与违法违规内容特征库）与模型异常告警为例外。
- 第三方模型未启用高阶安全防护（安全沙箱）时，按该模型的服务协议处理；方舟上的智谱 AI 模型服务协议（2026-07-07 版）没有不训练的承诺。

条件：

1. **只用承诺不训练的模型**：目前为方舟上的豆包系列，以及已确认启用安全沙箱的 `glm-5-3-flash` 接入点（2026-10-27 维护者在控制台确认，列入允许清单）。其它第三方模型须先确认启用了安全沙箱。
2. **账号没有数据授权**：没有签署《数据授权使用协议》、没有参加协作奖励计划（含奖励资源包），所用套餐（含 Bellis 的 Agent Plan）的条款不含数据授权。由维护者在控制台核对（PENDING，G2 前完成）。
3. **剩余风险**：合规审查与模型异常告警这两项例外作为剩余风险接受。
4. **运行时强制执行**：外发按主机授权；游戏适配包的合规声明列出允许的厂商与型号，清单外一律拒绝，配置与配置页面都不能越过；只发游戏窗口的画面，裁剪缩小后再发，不带任何观众信息。实现见[模型接入](modules/models.md#允许清单)。

同样适用于 Bellis 中收到游戏内容的模型：Bellis R-17 经 Agent Plan 的 `/api/plan/v3` 调用 GLM，是否走同一个已启用安全沙箱的接入点，须在 Bellis 侧于 T1 前核对（见 [Bellis P3 契约提案](plan/bellis-p3-proposals.md#bellis-侧的其他遗留)）。

## 其它游戏

每款游戏接入前，在其游戏适配包写合规声明，并在本文件登记需要维护者确认的用法。原神按 Bellis 合规，每一步开播前复核米哈游协议与账号风险。
