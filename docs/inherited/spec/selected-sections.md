## 来自 03-architecture.md

### 3.4 领域控制器内部职责

| 职责 | 作用 | 边界 |
|---|---|---|
| PolicyBackend | 在已授权目标下选择短动作；按后端声明复用语义编码、更新视觉状态，必要时对未提交连续候选做有界修正 | 没有自由目标采用、对观众播报、Iris直写或签发输入许可的权力 |
| SemanticActionInterpreter | 将明确的SemanticAction及适用证据编译为受限ControlFrame；检查profile／单位和组合冲突 | 不隐藏定位、候选编辑、重新规划或恢复决策 |
| InputBroker | 校验owner、上下文、时效、去重，提交／清理输入并提供真实已提交前缀 | 不执行模型自由决策；接纳或提交不等于游戏成功 |
| 只读定位适配器 | 基于指定目标和根截图选择区域、定位、回映坐标，产生GroundingResult | 不修改投票赢家、不驱动设备、不签发affordance |
| 恢复诊断职责 | 从既有Goal／Journal／证据形成ReflectionRecord与RecoveryProposal | 不自建权威记忆、不直接回滚世界，不阻塞安全停止 |

持续把目标保持在中央属于闭环控制器；镜头转动一个有限增量才属于动作解释器。界面控制器内部用VLM选择下一步，不等于另开高层Agent：其目标、动作集合、风险范围、费用和退出条件均已经受主控/运行时限制。具体协议见D05系列决定（第2.2节）。

#### 控制相关能力的归属

| 扩展 | 归属 | Bellis插件暴露内容 |
|---|---|---|
| ControlCapability与模式选择 | Game Runtime＋ControllerManifest；宿主保留通用Schema和质量门槛 | get_control_capabilities、模式/覆盖/不可用原因 |
| 细动作解释与ControlFrame合成 | Game Pack／控制器内部受信模块 | action_schema/profile版本及语义摘要，不暴露无限键鼠 |
| 本地快策略与局部预测 | Controller的可选PolicyBackend | 后端版本、时延范围、适用条件和验证报告 |
| PolicyPatch | 游戏侧校验与应用，Bellis主控采用提议 | propose_policy_patch、get_policy_update、cancel_policy_update、五种终态事件 |
| 控制健康与输入续租 | 游戏侧监督器＋Broker | control_quality／degraded／takeover_required投影 |
| 控制指标与示范记录 | 游戏Recorder与独立离线工具 | 经过权限过滤的报告/引用，不广播原始逐帧数据 |

上述不是六个独立的Bellis自治插件。一个通用game.bridge足够连接不同Game Pack；包、进程与算法可以分开演进，公开语义不能随实现私有字段漂移。

### 3.11 局部计算职责的部署与权威边界

定位器、编码缓存、候选编辑和恢复诊断优先作为现有Worker、PolicyBackend或RecoveryCoordinator的内部模块实现，不因名称新增进程。图中的GR与诊断之间传递只读依据和候选，不是两个互相等待资源的执行owner。

| 所属边界 | 保存／计算的内容 | 对外可见方式 |
|---|---|---|
| Game Runtime | 根视觉证据、DerivedView、GroundingResult、执行前缀、候选及修正决策 | Bridge按权限返回引用与语义摘要；高频内部轨迹不唤醒主控 |
| 当前计算Worker | ComputeArtifact及其精确依赖、容量和过期策略 | 可丢弃的局部缓存；命中和失效只作有界遥测 |
| Task/Recovery职责 | 失败诊断、可用反思项、恢复提议和已执行恢复的证据 | 既有Task结果、artifact.available和登记的恢复结果事件 |
| Bellis Host | 目标采用、任务/结果/结算、公开表达与外部投影 | 不复制游戏本地控制循环或第二个输入账本 |

高分辨率定位只在必要页面调用；稳定语义按变更重新编码；连续控制依时限选择简单或学习后端；恢复审查在停滞／失败／显式请求时运行。不存在“每次点击先串行跑四篇论文”的默认路径。

### 6.7 控制能力与服务

游戏Action引用已批准能力、模式/profile与结果契约；一个Attempt可执行多个本地ControlFrame，不逐帧通过Bellis。业务选择/消耗仍保持独立EffectIntent。兼容策略更新可通过有限Action登记PolicyUpdate引用；需要应用成功的后继等待该更新全部终态分流，其它工作继续。

service_requirements仅含service_ref、required_quality_ref和on_unavailable。on_unavailable的等待受Node/Activity期限限制；服务引用释放由其Session或显式Activity owner管理，不因一个临时Task结束而停服。

### 6.8 Action字段与业务policy位置

Action的字段表由Schema生成，详见附录B.3。Action层不再接收游离`policy`对象；投票规则必须放在`inputs.rules: PollRules`内，策略修改必须放在已登记PolicyPatchInput里。这样不会同时存在Action.policy、Plan.policies和业务inputs三套不清楚归属的配置。

Action.result_contract定义单工作真实结果与必要结算，Plan.completion_contract定义目标聚合。两者不可替代，也不可作为同一对象的兼容别名。权限scope只是引用，不能凭字符串扩大已授予范围。

### 6.10 感知、反思与恢复在计划中的位置

不新增Grounding、Reflection或Rollback节点类型。按需定位、诊断和恢复通过已注册Action及现有结果契约组合；不同Game Pack可以把只读定位封装在`game.validate_choice_context`内。附录A.2继续使用19节点两轮投票图，投票逻辑不依赖特定视觉算法。

定位Action完成但结果非FOUND时，只能重观察、选择已登记回退或请求人工，不触发选择。指针profile的choice_ref必须在游戏侧关联新鲜GroundingResult；非指针菜单导航可采用已验证的语义选择证据，不强制调用区域模型。

恢复提议不直接修改计划。确定性运行时或LiveDirector在已有预授权范围内采用完整恢复Action；改变目标／图／允许效果需正常PlanCandidate流程。没有安装的恢复能力必须静态拒绝。反思、审查、重观察和实际恢复均计入原recovery_budget_id；即使恢复另建Task也不能重置累计时间或次数。

### 8.6 局部计算的资源准入

区域重排、局部定位、编码缓存、候选编辑／打分、恢复审查分别登记资源与最大工作量。定位产生的多个crop数量有上限；候选块、编辑次数、审查点和反思项均有界。不允许一个“轻量辅助模型”以不计费、不计显存的方式默认常驻。

必要的本地连续策略按control_critical准入；剧情定位通常是受限交互计算，恢复诊断通常是auxiliary_analysis。静默／停止、当前音频消费和Broker watchdog不依赖这些模型完成。CPU/GPU不足时优先不接纳可选计算，按profile选择已批准的简单后端；没有可靠后端时报告unavailable，而不是隐式降级成无审核或长开环输入。

缓存淘汰、模型冷启动、ROI上传和失败重试的开销进入同一预算；共享GPU上需在游戏、OBS、皮套、媒体和必要模型共载时验证。独立进程、不同优先级或共享embedding均不构成硬资源隔离。

## 来自 17-content-safety.md

### 17.7 控制模型与策略提议的安全边界

游戏文本、画面中的提示和模型历史动作都是带来源的数据，不成为高层授权。快策略模型、VLM逐步控制和局部预测后端输出仍经过动作Schema、profile、上下文、时效、Effect和Broker检查；“本地模型”不是默认可信权限主体。

公开ContentGuard不被拉进逐帧输入硬依赖：游戏行动由已审查的能力/输入风险规则和本地安全机制限制；需要公开的文字和解说再走正常内容审核。不得因此把游戏屏幕中的未审核辱骂/私人信息自动朗读，也不能以不等内容模型为借口放宽输入权限。

不提供支付、账号、凭据或安全保护绕过能力；高层行为偏好不能修改这些限制。低风险界面探索仍只限已批准的可见区域和动作，未知来源提示不能要求任意上传桌面/安装脚本。新增训练/校准采集用途也需要独立许可，不随“允许玩游戏”自动获得。

### 17.9 可选模型产物的可信边界

截图、区域文字、候选动作、排名分数和反思文本均为数据，不是授权来源。新的GroundingResult、CandidateRepairRecord或RecoveryProposal必须通过当前对象scope、版本、来源与受信语义检查；模型写“已验证”不构成可信证据。

反思不能写进权限配置、系统人格、读音词典或删除记录；区域定位不能改写投票winner；候选修正不能新增离散效果。公开播报“我已恢复”“我已选中”只能依据相应真实结果，经现有双文本与内容审核后输出。未采用的诊断与失败分支全文不自动进入播报。

## 来自 19-local-channels.md

### 19.6 控制与示范通道分权

控制侧只接配对Runtime/受信controller和当前lease持有者；模型服务、示范记录器和离线训练进程没有Broker输入凭证。Recorder可订阅被批准的数据范围，不得反向注入frame、续租或修改policy。

ControlFrame与PolicyUpdate在目标侧分别做schema/身份/大小/频率/版本校验，不能把普通公开Overlay消息转发到控制端口。模型制品只按本地可信清单和兼容/质量证据加载，报告给出的任意URL或观众提供的模型文件不得自动下载运行。

原始帧、控制日志和模型数据集使用最小文件权限及独立保留规则；公开投影只暴露安全能力摘要和必要进展，不含执行令牌、坐标原始轨迹、受限制示范或未脱敏截图。

### 19.8 局部产物与恢复文件访问

计算与恢复产物引用只在所属会话／任务和用途下解析，不能使用任意文件路径、URL或序列化可执行对象作为payload。游戏save／sandbox snapshot由受信适配器在白名单目录和格式中管理，模型不能选择宿主根目录或直接下载恢复文件。

读取GroundingResult、反思或恢复结果使用现有认证通道及访问范围；Bridge只暴露所需引用和安全摘要，不将crop、原始失败日志和未来剧情文本默认发布到Overlay。示范记录器与离线模型仍没有输入／恢复／续租凭证。

### 20.7 控制模式的开播预检与接管

在第20.6节预检之外，控制模式另需检查：当前Game Pack/Profile/ActionSchema/Backend版本一致；可等待/持续模式分别有覆盖报告；本地观察年龄与控制时限在完整直播负载可接受；按键/相对位移/脉冲重复测试通过；人类接管清理与重新授权可核验。

continuous_local未通过时不影响已验证的只读陪玩或waitable_step模式，但必须在面板明确降级。部署不要把选择菜单测试通过当作战斗/移动能力通过。模型启动/新权重加载应在输入撤权、资源预算和监督允许的安全边界进行，不在拥挤的直播GPU上临时抢占当前输出。

接管后记录目标、实际输入范围和控制结果供审计；只有已独立开启示范用途时才记录训练样本。人工操作发生不等于正确专家行为，也不表示用户愿意保存键盘全量输入。恢复前确认实际画面、profile、目标、效果/清理和监督许可；后台策略返回不能自动夺回输入。

P5只读接入可以早于C0完成；任何自动游戏输入之前必须C0=PASS。P5验证仅持受监督测试许可，正式播出输入还必须目标profile真机控制门禁和相应P8通过。只支持菜单选择不得宣称已支持连续控制；C1–C5按实际启用范围追加验收，不通过管理面板临时开关绕过这些前置条件（第25.3节）。

### 20.8 定位与恢复的运营检查

游戏profile开播前列出定位路径、缺失／歧义出口、最大证据年龄、是否允许保存／读档、反思用途与当前剧情可见scope。面板分别显示“定位未完成”“效果未确认”“清理未确认”“恢复等待人工”，不能合并成一个可随意重试按钮。

操作员读档或重启游戏后先撤旧控制许可，核对旧操作隔离，重新识别现场并更新scope；自动恢复只能执行已明确批准的方法和有限范围。公开声音、Overlay历史和观众已经看见的内容不回滚。监督失效或急停时先停止相关效果，不等待反思保存或恢复诊断。

### 25.3 C0公共控制基线与公开/测试门禁

C0是任何真实自动游戏输入的前置，不是P0或无游戏聊天的无条件前置。C0契约可与P3/P4开发并行，完整验收在P5首个自动输入之前完成。只读采集不依赖C0，但绝不把只读接通记为P5完整PASS。

C0至少验证当前目标profile的完整ActionCommand/ControlFrame、四种时域、作用域代次、frame/pulse去重、Effect/Settlement、唯一Broker、部分提交、有限持键、失焦/接管/旧清理隔离。当前profile可只支持点击/短按；未使用的持续/轴/位移字段必须为空或中性，不能删字段或绕Broker。

| 启用范围 | 必需证据 |
|---|---|
| 交流＋投票，不输入游戏 | P0–P4适用出口＋P8；C0/P6/P7/C1–C5可关闭。 |
| 固定剧情有限选择 | P0–P5适用出口、C0 PASS、目标profile真机与P8；连续控制/策略更新不启用则不前置。 |
| continuous_local | C0＋C1＋目标profile/P8完整负载；启用兼容调参加C2。 |
| test_only有限真机验证 | C0及适用P3执行安全出口、操作员批准白名单/期限/效果预算、应急就绪；禁止公开播出。 |

test_only不要求尚未产生的P5真机报告作为P5测试本身前提；正式public必须等待目标P5/P8证据。ExecutionGrant.mode与状态已登记第11.4.18节，不能通过配置布尔量绕过。

C1–C5是按需启用的独立扩展规范，统一维护在本节；核心阶段不因此承担全部扩展实现。

### A.4 从推进游戏切到复盘

操作员提出新的活动目标/策略→候选基于当前revision准备→标出保留的剧情采集服务、已完成证据、正在安全播放的无关表达→受影响游戏推进Task到检查点并清理→重新检查页面/效果→本地PlanRef提交→外部Runtime实际应用回执→新增复盘分析Task。

不清空整个Session、不重新读已播剧情、不重开已完成投票、不把游戏暂停理解成时间冻结。已经结束的Task保持结果，尚未运行后继可以重排；旧Goal相关候选失效，无关状态继续。

### A.6 兼容调参与聊天并行的完整轨迹

```text
Game Task A / Attempt A1：continuous_local在Policy r12下跟踪目标
→ 本地持续使用新观察产生短ControlFrame，Broker有界续租
→ Bellis正在播放已审核Utterance U；新普通弹幕只排队
→ 主控在允许决策点采用参数候选P（base=r12，目标/实例/期限绑定）
→ Game Runtime登记PolicyUpdate P；主控立即取得外部句柄继续调控
→ P校验通过，等待一个有界本地决策边界；A1在r12下继续
→ 本地再次校验，应用r13，固定effective_control_seq，隔离旧未执行后缀
→ 新帧使用r13；不重开A1、不释放根owner、不重播U
→ control.policy_applied进入Bellis；此时只能说参数已应用
→ 后续观察显示目标更居中／距离改变，才产生对应进展事件
```

若另一个更新先应用、目标已变或候选过期，P被拒，不能改base重试。如果r12也已不适用，本地立即按能力降级，不能等待云端替代方案。控制帧与策略revision是游戏侧权威记录，Bellis不替它更新“已应用”。

### A.7 感知冻结与输入续租

假后端持续返回同一个capture_sequence而控制循环仍正常tick：超过该能力观察有效窗后，健康续租拒绝，Broker在许可边界释放本系统保持键并拒绝旧帧。原Task按已注册降级/接管路径推进，普通弹幕和安全字幕可以继续。

反例测试：界面静止但新的捕获序号与有效采集时间持续产生，不能仅因像素hash相同就误报冻结。两种情况都要记录实际依据、时限与停止边界，不用“有心跳”证明闭环正常。

### A.8 组合输入重复、迟到与未知效果

ControlFrame F包含后退保持状态、相对镜头增量和一个独立短按。F重复到达：只返回原receipt，不再次转镜头、短按或延长保持时间。下一纯状态帧可以改变保持集合，但不能顺便重放F的脉冲。

若后端只确认部分输入已提交，标PARTIAL/UNKNOWN和可确认子集；涉及业务Effect的短按进入对账，不能换frame/pulse ID再次发送。旧owner交出控制后到达的KEY_UP不会释放新owner的状态；做不到可靠交接的后端不得进入该模式。

### A.9 策略已应用但回执丢失

目标Runtime已经应用r13并保留原事实，但Bellis没有收到确认：外部投影标未知，保持update_id和当前owner。主控不得重新提交r12→r13来“补上”；通过get_policy_update查询原event_id、revision、生效边界与证据，原事实重放只消费一次。查询不是新应用事件，不能把查询时间当applied_at。若目标自身已因证据缺口终态UNKNOWN，则以Reconciliation追加查明的历史事实而不重开终态；若仍不可靠，按目标侧可确认条件控制或降级，宿主不宣布策略成功。

即使P最终APPLIED，也不会自动结束跟踪Task；正常Task结果仍等待目标证据、Effect和Settlement。恢复历史未知不复活任何终态Attempt。

### A.10 人工接管与可选示范

人工接管优先撤销自动输入，完成可核验清理；未开启示范用途时只保留必要运行审计。已获许可时记录接管前观察、真实输入组合、当前目标/profile、来源与结果，标为rescue或其它实际类型；不自动标专家正确。

离线整理、训练和真机批准完成后才可能部署新后端；原直播里的接管事件不自动修改当前模型、不回灌未经审核的Iris事实，也不自动重新取得输入授权。
