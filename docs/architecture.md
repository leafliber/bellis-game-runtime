# 总体架构

本文只写跨模块的结构：进程、权威、连接、失效、控制的组织、模型调用、契约与扩展分类。各模块的设计见 [modules/](modules/)，编号的含义见[技术基线](plan/tech-baseline.md)。Bellis 的 D-xx、R-xx 指 [Bellis 技术基线](https://github.com/leafliber/bellis/blob/main/docs/plan/tech-baseline.md)中的条目。

## 定位

Game Runtime 为 Bellis 提供游戏能力：采集画面与声音、读懂画面与剧情、在授权范围内操作游戏，并把局面、决策点和已发生的动作报给 Bellis。逐帧控制不经过 Bellis（Bellis D-04、D-27）。

管理方式按 Bellis 的规划对齐（GD-02）：授权从上往下给，数据从下往上报；Bellis 已有的概念（安全核、执行许可、插件、服务、profile、关键平面）在这里沿用同样的含义，需要时再扩展。

## 术语

| 术语 | 含义 |
| --- | --- |
| 主进程 | Python 写的 Game Runtime 主体：感知、剧情理解、规划、策略与游戏桥的语义部分（GD-01） |
| 实时核 | Rust 写的独立进程：采集、帧环、唯一的输入代理（GD-01）。在游戏侧相当于 Bellis 的安全核 |
| 帧环、音频环 | 主进程与实时核之间的共享内存环形缓冲，存放采集到的帧或声音及其元数据 |
| 控制模式 | 动作的节奏：逐步模式（看一帧、做一个动作、再看一帧）或连续模式（按固定频率下发动作块）（GD-04） |
| 策略后端 | 决定动作的组件：快路径、通用视觉智能体、VLA 等 |
| 控制产出者 | 当前唯一有权向实时核提交动作的主进程组件：逐步模式下是逐步控制器，连续模式下是当前的连续策略后端 |
| 通用视觉智能体 | 不依赖游戏专门规则、看画面决定下一步动作的策略后端，用 VLM 实现 |
| 快路径 | 游戏适配包为高频或有时限的画面提供的确定性处理，命中时代替通用视觉智能体决定动作 |
| 画面状态 | 画面状态服务给出的稳定性、画面类型、来源（签名、检测、观察）与置信度；画面类型取自通用分类（GR-32） |
| 动作块 | 控制产出者交给实时核的一段带时间戳的动作，附基准帧与有效截止时刻 |
| 输入许可 | Bellis 安全核授予的 `game.input` 执行许可（Bellis D-31、D-34） |
| 游戏适配包 | 针对一款游戏的适配：必需的窗口识别、动作白名单、合规声明、期望分辨率与语言版本，以及可选的快路径（GD-04、GR-16） |
| 本地数据目录 | 版本库外、只在本机的目录，存放从游戏派生的数据、模型制品与运行数据；Windows 上缺省为 `%LOCALAPPDATA%\BellisGameRuntime`，其它平台为 `$XDG_DATA_HOME/bellis-game-runtime`（未设时为 `~/.local/share/bellis-game-runtime`），环境变量 `BELLIS_GAME_RUNTIME_DATA` 可改到别处 |

阶段编号 G0–G3 见[路线图](plan/roadmap.md)。Bellis 的游戏控制分层也用 G0–G4 编号，本仓库提到这些层时只写层名，不用编号。

│ 动作块与心跳 ────────────────────────►│ │ 许可与持键账目 · 释放 · 低层钩子  │

| 层 | 对应 Bellis 的概念 | 负责 | 不负责 | 替换 |
| --- | --- | --- | --- | --- |
| Bellis 安全核 | 安全核 | 能不能动：授权、输入许可、急停、监督模式 | 怎么玩 | 永不热替换 |
| Bellis 游戏桥插件 | sidecar 代理 | 连接与握手，把 Game Runtime 发布为 Bellis 内的服务，续约输入许可，把上报转为 Bellis 的事实 | 逐帧控制 | 普通插件 |
| 实时核 | 安全核 | 最后一道把关：本地强制许可、白名单、前台、持键账目与释放 | 任何决策 | 不热替换；只在没有输入许可时更换 |
| 主进程关键平面 | 关键平面 | 当前游戏适配包与当前控制产出者 | 授权 | 只在输入已全部释放时切换 |
| 主进程普通插件 | 普通插件 | 感知与理解，只产出数据和候选 | 提交输入、签发许可、对观众说话 | 可热替换 |

对应 [Bellis 游戏控制分层](https://github.com/leafliber/bellis/blob/main/docs/architecture.md#游戏控制分层)：主播决策层在 Bellis；规划与理解层、快策略层在主进程；输入代理层与急停层在实时核。

## 权威

- **实时核是唯一的输入写入者。** 它只在三件事同时成立时发出输入：输入许可有效（令牌等于当前值且未过期）；当前控制产出者的身份、代次与心跳有效；帧环中最新的帧未超过动作允许的年龄。任一项不成立就不发，并释放本许可负责的全部输入。
- **单写者。** 任何时刻只有一个控制产出者；实时核拒绝其它产出者和旧代次的动作。更换控制产出者时先释放输入，再换。
- **扩展没有权威。** 感知、理解与策略组件只产出数据和候选；分数、置信度和排名都不构成许可，也不证明效果已发生。
- **游戏内容是不可信数据。** 画面、OCR 与模型读出的文字只是数据，不能作为指令改变目标、权限或配置；进入 Bellis 后按不可信来源处理（Bellis 安全核的 Rule of Two）。
- **长期记忆只经 Bellis。** Game Runtime 不直连 Iris。
- **游戏与 profile 由操作员选择。** Bellis 决策模型只能在已加载的游戏适配包声明的能力内提交目标，不能更换游戏、适配包或 profile。

## 进程与连接

| 进程 | 运行身份 | 由谁启动 |
| --- | --- | --- |
| 主进程 | 当前用户、交互会话、非提权 | 操作员以 Game Runtime 自己的启动命令启动，从 SecretStore 读取 Bellis 本次会话的连接信息（Bellis R-23） |
| 实时核 | 游戏不提权时不提权；游戏提权时提权（SendInput 不能跨完整性级别注入） | 不提权时是主进程的子进程；提权时由维护者注册的计划任务按需启动（[实时核](modules/realtime-core.md#启动与生命线)） |

- **非提权一方创建全部进程间对象，提权一方只连接。** 管道与共享内存都由主进程创建，实时核连接并写入；这与 Bellis“宿主永远做服务端”一致。跨完整性级别的可达性经 [GS-03](plan/spikes.md) 实测成立。
- **全部本机通道用 `bellis-channel/1`**（Bellis R-05），认证前不传任何数据；画面帧与声音不走管道，只走共享内存（[核协议与本机通道](modules/core-protocol.md)）。

| 连接 | 服务端 ← 客户端 | 内容 |
| --- | --- | --- |
| 语义连接 | Bellis 宿主 ← 主进程 | 目标、局面、决策点与候选、暂缓推进、已发生的动作、健康（[游戏桥](modules/game-bridge.md#连接)） |
| 控制连接 | Bellis 宿主 ← 实时核 | 只有输入许可续约、停止、输入已释放与实时核健康；主进程只能让输入停下，不能让输入继续 |
| 核连接 | 主进程 ← 实时核 | 动作块、控制产出者心跳与回执等，见[核协议](modules/core-protocol.md#核协议) |
| 帧环、音频环 | 共享内存，主进程创建 | 帧或 PCM、采集时刻（同一单调时钟）、窗口与 DPI 变换版本 |

不接 Bellis 时以[独立运行](modules/game-bridge.md#独立运行)开发与测试：操作员控制台代替 Bellis 宿主作两条连接的服务端，主进程连它的操作员连接，实时核连它的操作员许可连接。

### 失效与释放

| 失效 | 结果 |
| --- | --- |
| Bellis 宿主崩溃或卡死 | 续约停止，实时核在许可到期后自行释放全部输入（目标：到期到释放 ≤100ms，PENDING） |
| 主进程崩溃或卡死 | 实时核在控制产出者心跳超时后释放全部输入并待命；核连接断开或 stdin 读到 EOF 即释放后退出（[生命线与 panic](modules/realtime-core.md#生命线与-panic)） |
| 采集冻结 | 帧超过动作允许的年龄，实时核停止发出输入并释放；控制线程仍在运行不构成续约依据 |
| 许可过期、旧代次的动作块、更换控制产出者 | 实时核不发出输入并释放全部持续状态 |
| 实时核崩溃 | 没有进程发出按键抬起，是残余风险。缓解：实时核保持最小，panic 即退出；崩溃后有限次自动重启（GR-35，[启动与生命线](modules/realtime-core.md#启动与生命线)），重启后先释放全部输入再接受动作；真实后端上新实例以 `GetAsyncKeyState` 核验，仍读作按住的键补发抬起（[持键账目与释放](modules/realtime-core.md#持键账目与释放)）。实际效果 PENDING |
| 真人接管、第三方注入、急停 | 实时核释放全部输入并在本地撤权，许可源须换发更大的令牌；交还控制只能由操作员执行（[接管与急停](modules/realtime-core.md#接管与急停)） |
| 游戏窗口失焦 | 实时核不发输入并释放全部输入，从不把游戏切回前台（[注入](modules/realtime-core.md#注入)） |

## 控制的组织

控制模式只管节奏，策略后端决定动作（GD-04）：

| 控制模式 | 节奏 | 策略后端 | 适用 |
| --- | --- | --- | --- |
| 逐步模式 | 看一帧、做一个动作、再看一帧 | [逐步控制器](modules/step-control.md)：快路径命中时由快路径决定，否则由通用视觉智能体决定 | 剧情游戏的全部画面；即时游戏的菜单、对话、商店与解谜界面 |
| 连续模式 | 按固定频率下发动作块 | VLA、反馈控制等 | 即时游戏的探索与战斗 |

- **统一动作空间**：逐步模式有点击、短按、滚动、等待、开决策点、上报与调用技能，连续模式另有按住、轴与鼠标相对位移。开决策点与上报不产生输入，由主进程处理；调用技能在主进程展开为原子动作后才到实时核（[技能](modules/step-control.md#技能)）。没有输入文字的动作。
- **适配成本**。每款游戏只须提供[游戏适配包](modules/game-adapter.md)的必需项就能进入逐步模式。快路径可选。计时执行须符合[决策点](modules/step-control.md#决策点)的证据要求。
- **业务选择**须有当前决策实例。独立监督时由操作员回应，接入 Bellis 时由游戏桥接收授权的选择。逐步控制器核对动作风险与决定的有效性（[逐步控制](modules/step-control.md#动作风险)）。
- **更换控制产出者**由[模式仲裁](modules/step-control.md#模式仲裁)按确定性规则决定，先释放输入再切换。
- **策略后端**都按同一份[策略后端契约](modules/step-control.md#策略后端契约)接入，离线回放基准可替换后端对比。

## 仓库与目录

| 仓库 | 内容 |
| --- | --- |
| [bellis](https://github.com/leafliber/bellis) | 宿主、安全核、游戏桥插件、游戏桥契约的源 |

本仓库的目录（GR-29），各目录在首个实现时创建：

| 目录 | 内容 |
| --- | --- |
| `core/` | Rust cargo 工作区，包含实时核、核协议类型与游戏桥控制类型 |
| `runtime/` | Python uv 项目：主进程与插件 |
| `games/<id>/` | 游戏适配包：声明文件与钩子（GR-31） |
| `tools/` | 离线工具与合成游戏夹具 |

| `vendor/bellis-protocol/` | 锁定的 Bellis 游戏桥生成物，附来源提交与摘要 |
| `docs/` | 文档，分工见[文档索引](README.md) |

统一检查入口为 `uv run check`，在仓库根目录运行：根目录放一个最小的 `pyproject.toml`，以 uv workspace 纳入 `runtime/`、`tools/` 与 `protocol/`，`check` 脚本由工作区成员 `tools/check/` 提供；它依次运行 `ruff format --check`、`ruff check`、pyright、`cargo fmt --check`、clippy、`cargo test`、pytest、生成物核对、[Bellis 契约锁定副本核对](modules/game-bridge.md#契约)与[适配包校验](modules/game-adapter.md#校验)，每一项都运行，最后汇总，任一项失败即以非零退出；cargo 排在 pytest 之前，因为 pytest 要用 cargo 编译出的程序；`uv run check --linux` 在本机 Docker 的 Linux 容器里跑同一检查，覆盖非 Windows 的代码路径；提交前与合并 PR 前都在本机运行这两条，不用托管 CI（GR-29）。

## 平台

Windows 11 x64 是唯一的生产平台（Bellis D-11）。Windows 专有部分（采集、输入、钩子、跨完整性级别的进程间对象）放在接口后面并提供假实现；完整检查在 Windows 真机与本机 Linux 容器上运行，macOS 不验证；自动测试通过不等于真机通过。Rust 用 `windows` crate，Windows 专有代码用 `cfg` 隔离（GR-01）。
